# 可移植运行契约

## 目标

本 Skill 要安装到没有代码仓、没有页面接口知识、没有自建 HTTP 能力的 Agent 平台。业务执行只依赖：

1. 宿主能够读取 Markdown Skill；
2. 宿主已安装并能够调用 `contract-cli`；
3. 当前会话已完成对应 profile 的 User 授权；
4. CLI 提供[页面接口契约](page-api-contract.md)要求的 `api call --channel web` 受控页面通道；只有普通合同分类字段缺失时，才额外使用 CLI 内置的只读 `contract search` 辅助核对。

## 随包边界

- 运行时包仅包含 `SKILL.md`、`agents/openai.yaml` 和 `references/*.md`。
- 不携带或执行 Python、Node、Ruby、Shell 等业务运行器。
- 每次业务工具调用只启动一条允许的 CLI 命令，由 Agent 保存计划、逐条调用和登记结果。禁止生成、保存或执行 `.py/.js/.sh` 编排脚本；同样禁止内联 `python -c`、`node -e`、Shell `for/while`、`xargs`、`eval`，以及用管道、重定向或外部解析程序代替 Agent 处理业务数据。脚本内部仍调用 CLI 也不是例外。通过宿主 Shell 启动单条 CLI 可以，不得在该外壳里增加业务循环或处理逻辑。
- 不自建 `/tmp` 或其他位置的业务中转文件。宿主自动生成的 CLI 结果归档不是 Agent 自建文件，可用宿主自带只读工具完整读取；每份归档必须绑定原调用的身份、对象、参数和读取时点，不能混用其他任务文件。普通回复不展示归档路径。
- 不要求 Agent 拥有本地代码仓、源码检索能力或自行实现 HTTP；页面请求由 contract-cli 代发。
- 不读取 CLI 配置文件、token、cookie 或系统钥匙串。
- 不使用 curl、浏览器抓包、直接 HTTP 或任意 URL/path。只调用包内页面接口契约白名单中的相对 path。
- 测评脚本可以存在于仓库的 `tests/`，但不进入 Skill 运行时包，也不能成为真实业务操作的前提。

## 启动检查

首次使用、授权异常或迁移到新 Agent 平台时：

1. 检查 `contract-cli --version` 可执行；
2. 检查对应 profile 的 User 登录状态；
3. 读取 `contract-cli api call --help`，确认 `--channel web`、User 身份和相对 path 能力存在；
4. 用只读任务查询验证授权与业务可见范围；
5. 写动作还要确认本 Skill 能完整读取详情、动作权限、人员和动作特定回查字段。

如果 CLI 返回结果被宿主截断，先用宿主提供的只读结果展开/分段读取能力取得同一次调用的完整结果；不能按截断片段假定其余为空，也不能写脚本补读。无法取得完整结果时说明本次查询不完整；缺少动作所需证据时停止相应写入。无关且证据完整的查询仍可展示。

## 安装与规则版本

- 安装 CLI 与注册 Skill 是两个验收点；确认目标宿主能发现本目录并加载 `SKILL.md` 和全部引用。不把 npm 安装成功当作 Skill 已生效。
- 本规则版本固定为 `3.1.7`，`version` 与 `metadata.skill_version` 应一致。CLI 包版本、构建号单独记录，不覆盖 Skill 的规则版本。不能仅看到 CLI 版本就声称规则已更新。
- 宿主不热更新技能时，在注册/替换完成后使用新会话。身份授权是否可复用仍以 CLI 在新会话中的实际状态为准，不复制凭据。
- 上述检查用于安装验收，不要求普通用户每次查询都理解版本、目录或注册细节。

普通业务回复不主动展示这些检查，也不在生产使用中反复强调环境。

## 能力不足时的行为

- CLI 不可执行或 User 未授权：说明当前无法连接到合同能力，并提示完成 CLI 安装或 User 授权。
- 页面通道或任务列表接口不可用：不能声称已查到全部任务。
- 加签、转办或抄送所需详情、权限或写后核验字段缺失：直接停止该动作，说明当前无法安全核验，不得只凭写接口返回继续。
- 审批通过、拒绝、完成盖章或完成归档：不进入本 Skill 的页面写入链路，改由宿主匹配其他专用 Skill；找不到则报告不支持。
- 任何情况下都不能自行增加页面接口、改用未知开放平台 API、自建脚本或直接 HTTP。
- 任务数量多、工具输出长或担心调用次数不是启用脚本、循环或临时数据文件的例外。若宿主无法逐条调用并保存终态，停止受影响的写入；不得降级为临时程序。

## 会话与工作目录

CLI 授权可能与 profile、宿主会话或工作目录绑定。Skill 不改变当前工作目录，也不复制授权信息。若同一 profile 在当前会话不可用，只报告授权不可用；不能把它误判为业务上“没有待办”。

## 可移植验收

至少在一个没有源码仓、没有 Python、没有直接 HTTP 权限的干净 Agent 宿主完成：

- 完整分页查询本人任务；
- 合同、合同组、分类和人员消歧；
- 页面通道、详情或动作核验字段不可用时安全停止；
- 页面通道与核验字段齐备时，分别完成一次加签、转办、抄送，以及一次“并加签 + 抄送 + 转办”的可执行复合操作；
- 验证“前加签 + 抄送”只提出“抄送在前、前加签在后”的可执行方案，取得确认后才执行，并在前加签后停止；验证前/后加签与转办同现时在任何写入前拦截并让用户选择；
- 审批通过、盖章、归档请求能够正确路由或明确不支持；
- 普通输出不泄露技术 ID、请求标识、profile 或原始错误。

## 平台安全边界

当前通用 `api call` 只负责页面通道、User 登录态和 `/open-web/web/**` 路径前缀校验，不会依据本 Skill 名称强制限制具体 path，也不会限制 `task/run` 的命令码。本 Skill 的 path 与命令码白名单属于指令级约束，不得描述为 CLI 硬拦截。

需要硬安全边界的部署，应由 CLI 提供以下任一能力后再认定为安全门禁：

- 加签、转办、抄送三个专用结构化命令；或
- 可绑定 Skill 的 path allowlist，并对 `task/run` 仅允许命令码 `3、6、18、19、20、21`。

在平台未提供该能力前，部署评审必须明确接受“指令级白名单”的剩余风险；Skill 不能通过增加文案伪装成硬约束。
