# 可移植运行契约

## 交付目标

本 Skill 面向没有智书合同业务代码仓、没有通用 HTTP/MCP 接口调用能力，但能够安装并执行 `contract-cli` 与完整 Skill 包的 Agent 平台。业务 Agent 只负责理解用户意图、调用 Skill 公开命令和组织业务回复；页面接口、登录态读取、权限校验、确认绑定和写后复查都由随包运行器完成。

完整安装包至少包含：

- `SKILL.md`
- `agents/openai.yaml`
- `references/`
- `scripts/page_api.py`

`tests/` 可以不进入生产安装包，但必须在候选版本发布前执行。只复制 `SKILL.md`、遗漏 `scripts/page_api.py`，或依赖某个本地项目仓库中的同名脚本，都属于不完整安装。

## 运行依赖

- `contract-cli >= 1.9.4`，并存在有效的 `contract-test` User 登录态；
- Python 3；
- curl；
- 能从 Skill 安装目录执行命令；
- 能访问运行器固定的 test 页面服务。

首次业务调用执行：

```bash
python3 scripts/page_api.py runtime-check
```

检查失败时只说明缺失的 CLI、运行时或登录条件，不读取或展示本地凭证内容，不自行改用 HTTP、浏览器网络面板或其他接口工具。

## 唯一允许的业务调用面

Agent 只能通过 `python3 scripts/page_api.py <公开子命令>` 使用本 Skill。允许的子命令由 `--help` 列出，包括运行检查、格式化待办 `task-list`、原始任务查询、目标定位、人员与类型解析、任务详情、动作候选表格，以及审批通过、加签、转办和抄送的预览或执行。

普通业务请求中禁止：

- 导入 `page_api.py` 后直接调用内部函数；
- 使用 `python -c`、临时脚本或 REPL 绕过公开子命令；
- 自行读取 `~/.contract-cli` 或其他凭证文件；
- 自行拼装 curl、HTTP、OpenAPI 或页面接口请求；
- 通过浏览器开发者工具复制或重放请求；
- 修改运行器、计划指纹或响应数据后继续执行；
- 在运行器失败时改用模型猜测任务、人员、权限或执行结果。

维护人员在用户明确要求诊断或更新 Skill 时可以检查源码和测试，但维护动作与业务写入必须分开；源码检查不得成为执行真实审批的旁路。

## 表格输出硬契约

普通待办查询统一交给 `task-list`，动作候选和批量动作的最终可执行范围交给 `task-table`。两者都返回：

- 固定六列：序号、对象、名称、编号、当前节点、当前处理人；
- `candidateCount`：最终可执行数量；
- `displayedCount`：本次必须展示的行数；
- `remainingCount`：尚未展开的行数；
- `displayMode=full|summary`；
- 可直接使用的 Markdown 表格。

阈值只以最终可执行数量计算：

- 1–20 条：`full`，必须完整展示全部行；
- 超过 20 条：`summary`，首批展示前 10 行并说明剩余数量；`task-list --page-index 2` 从 11 连续编号；
- 被拦截、已重复处理或不再属于当前待办的任务另行汇总，不计入上述阈值。

Agent 不得自行减少列、把完整表格改成“示例”，也不得把原始命中总数误当成最终可执行数。

## 发布与安装检查

候选包交付其他 Agent 平台前至少验证：

1. 在一个没有业务代码仓的空目录中安装 `contract-cli` 和完整 Skill 包；
2. `runtime-check` 成功，且不暴露 token、配置路径或员工/任务内部 ID；
3. 不读取源码，只使用公开子命令完成一条只读查询和一条预检；
4. 用“命中 30、可执行 20、拦截 10”的夹具验证完整六字段 20 行输出；
5. 删除 `scripts/page_api.py` 后必须明确报安装不完整，不能退化为直接接口调用；
6. 写操作仍需执行契约规定的用户授权、实时复检、指纹校验和写后复查。

当前候选只面向 test。未来生产化时应优先把页面原子动作下沉为 contract-cli 原生命令；在此之前，不得把本候选描述为“纯 contract-cli 原生命令能力”。
