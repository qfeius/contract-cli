# 智书合同加签、转办与抄送

只处理当前 `contract-cli` User 身份可见、可操作的智书合同任务。用户提供业务目标；任务、流程、节点、合同和人员标识由 CLI 查询衔接，普通回复不展示技术 ID。

## 能力路由

在调用工具前拆出全部动作：

- 本 Skill 支持查询、加签、转办、抄送，以及由这三类动作组成的可执行复合计划。
- 审批通过、拒绝、完成盖章、完成归档不属于本 Skill。先退出本 Skill，匹配宿主已安装且描述明确支持该动作的专用 Skill；找到后由该 Skill 独立判断和执行，找不到就直接说明当前不支持。
- 混合请求包含本 Skill 与其他 Skill 的动作时，明确拆分归属，不把外部动作伪装成本 Skill 能力，不静默删除任何一步，也不承诺跨 Skill 事务。只有用户明确同意先处理本 Skill 支持的部分时才继续。
- 用户要求代另一位审批人办理、处理“某人的全部审批”或指定其他操作者时直接停止；只能处理当前登录用户本人的责任。
- 撤回、催办、终止、修改流程定义、抄送附件等未声明能力同样先路由专用 Skill；没有匹配能力时说明不支持。

人员查无结果只表示“没有找到该人员”，不能推断为离职。接口明确返回停用、删除或其他状态时，才可陈述该状态。

## 依赖与读取顺序

- 查询、分页和技术命令先读[CLI 能力契约](references/cli-contract.md)。
- 定位合同、合同组、分类或节点时读[目标定位](references/target-resolution.md)。
- 加签、转办、抄送或复合操作时读[动作语义](references/action-semantics.md)和[执行契约](references/execution-contract.md)。
- 组织候选、确认与结果时读[交互契约](references/interaction-contract.md)和[输出契约](references/output-contract.md)。
- 首次运行、授权异常或跨 Agent 平台安装时读[可移植运行契约](references/portable-runtime.md)。

本 Skill 不携带 Python、Node、Shell 等业务运行器，不读取凭据文件，不使用 curl，也不接受用户提供的 URL 或任意接口路径。

## 开始前检查

默认使用生产 `contract` profile。只有用户明确处于测试或验收环境时才使用 `contract-test`；同一计划的查询、人员解析、预览、写入和回查必须保持同一 profile、租户和 User 身份。正常业务回复不主动展示环境或授权实现。

写动作开始前，必须确认当前 CLI 的 `--help` 中真实存在对应结构化子命令，并满足[CLI 能力契约](references/cli-contract.md)中的预览令牌、User 身份、写后回查和结果不确定处理要求。缺少任一项时停止该动作，说明“当前 CLI 尚未提供安全执行能力”；不得退回通用 API、页面接口、自建脚本或直接 HTTP。

## 业务主线

1. **读取完整任务范围。** 使用结构化任务命令从第 0 页开始完整分页；查询本人全部任务时不暗加业务类型过滤。按任务实例去重，并校验页码、总数和是否还有下一页。
2. **解析业务目标。** 按用户给出的合同、合同组、编号、分类、节点、时间或自然语言指代筛选。默认加签、转办、抄送只定位真实审批节点；盖章、归档等其他节点必须由用户明确指定。
3. **解析人员。** 完整分页查询候选，保留姓名、部门、邮箱、工号和状态。同名时用可核验业务信息消歧；仍不能唯一则停止。
4. **核对可执行性。** 使用任务详情和 CLI 预检结果检查当前状态、节点类型、本人责任、动作权限、重复抄送和人员可选性。搜索命中不等于可写。
5. **形成业务方案。** 展示合同、节点、当前处理人、动作顺序、接收人、关键参数、可执行与拦截数量。除执行契约允许直接发送的单条抄送外，只请求一次业务确认。
6. **逐步执行并回查。** 每一步写前重新预览，只有业务计划仍与已确认内容一致才使用 CLI 返回的内部确认令牌执行。每一步写后先核验业务结果，再进入下一步。
7. **报告真实结果。** 按已完成、确认未生效、待核验、失败和未执行分类。结果不确定时停止后续写入，不自动重试或切换通道。

## 查询我的待办

用户只说“查我的待办”“有哪些待办”“继续看”“第 N 条”，且没有飞书任务、项目或截止日期语义时，直接查询智书合同任务，不让用户补技术条件。

固定展示六列：序号、对象、名称、编号、当前节点、当前处理人。

- 1–20 条全部展示；超过 20 条先展示分布、前 10 条和剩余数量。
- “继续看”沿用同一候选快照和连续序号；筛选或重新查询后重新编号。
- 合同组标为“合同组”；没有编号时留空，不使用组内合同编号代替。
- 当前处理人来自目标节点真实未办人员；超过三人压缩为“你、某某等 N 人”，用户要求时再展开。
- 空结果只表示当前 User 的本次完整查询没有任务，不表示租户全量不存在。

## 完成标准

- 查询：完成 0 基分页、全业务类型覆盖、去重和总数一致性检查后，才可说“全部”。
- 写入：结构化 CLI 请求成功且动作特定的写后记录证明目标、人员、模式和顺序正确，才报告完成。
- 抄送成功只表示已发送，不等于对方已读。
- 转办成功必须证明责任转给指定人员，不能只凭本人待办消失。
- 批量或复合操作逐条列出失败、待核验和未执行项，不把部分成功说成全部成功。
- 技术 ID、确认令牌、请求参数、接口路径、profile 和原始错误只保留在工具上下文，不进入普通业务回复。
