# 查询合同协商群 ID

用户提供合同 ID，返回当前用户可读合同关联协商的当前轮次飞书群 ID 和群状态。权限与合同正文页面的群信息读取能力一致，不另加协商参与者或 COOPERATION_DATA 门槛；每个接口仍执行服务端鉴权。合同已经进入审批或已过审批，也执行同一流程。

本 Skill 使用页面标准合同详情读取，允许该读取正常发生的正文/编辑器初始化或访问凭证生成，不承诺完全没有副作用。若用户明确要求连这些正常查看行为也禁止，应说明本链不适用并停止，不擅自执行或假设有未上线的纯元数据替代。

## 输入与执行上下文

- 必需输入为一份合同的真实合同 ID。沿用同一轮对话已确认的合同；合同编号、协商 ID、轮次 ID、合同组 ID 不能代替合同 ID。仅给名称或编号时，先由已安装的合同搜索能力定位合同；多个候选时由用户选择。
- 通过 `contract-cli` 执行，固定 `--as user`，沿用已确认的环境、租户、profile 和该环境的个人授权。每条请求显式传同一 `--profile <profile>`，不从 profile 名推断目标环境。
- 复用当前已确认的有效授权。需配置或恢复授权时，按技能名加载宿主的 `auth`、`contract-cli-shared` 公共 Skill；宿主不能发现它们时报告缺少的依赖，不假定固定安装目录。不要求用户提供 Token、Cookie、App Secret 或内部轮次 ID。
- 查看 `contract-cli api call --help`，确认当前正式 CLI 支持本参考的 `--channel web`、`--query`、`--input-file` 和 `--raw`。两步使用现有页面接口，不依赖合同简要接口新增字段，也不换用更窄权限的协商详情。
- 本 Skill 的完整请求协议见[接口与结果](references/api.md)。不需要安装 Builder 或读取源码，不能依赖作者原聊天中的信息。

## 查询步骤

### 1. 按合同读权限取得关联与当前轮次

调用接口参考中的 `GET /open-web/web/clm/contract/info`，query `contractId` 来自用户已确认的合同 ID，只传本参考规定的参数。

确认 `data.contractId` 与目标合同一致，读取 `data.cooperationId` 及 `data.cooperationRoundId`。三个 ID 必须保留完整原文，协商与轮次 ID 须为可用的正 Long。名称、编号仅供展示，可为空；合同阶段仅供排障核对，默认不展示，也不作为查询开关。

字段直接位于 `data` 下，不是 `data.contractInfo`。`data` 为空、合同 ID 不符、关联或当前轮次缺失/null/非法时，说明合同详情未提供可用关联/当前轮次并停止；不能推断未建群，也不能合成字段或猜历史轮次。

仅保留本场景必要的合同/协商/轮次 ID、名称、编号与排障阶段值。忽略其余详情内容，不保存或回显完整详情、正文、文件 URL、编辑器访问凭证等。

### 2. 查询当前轮次的群绑定

将步骤 1 的真实 `cooperationRoundId` 原文写入请求体 `cooperationRoundIds`，每次只查询一个轮次。调用 `chatGroupStatus`，独立读取返回的群状态、`openChatIds` 和当前用户在群情况。只报告本次取得的轮次快照，不承诺两次请求原子一致。

飞书群 ID 来自 `openChatIds`。`chatGroupIds` 是内部群记录 ID，合同详情或搜索中的 `group_id` 是合同组 ID，均不能当作飞书群 ID。

不调用 `briefInfo`、`searchV2`、结构化协商详情或页面 `cooperation/info` 回退：它们不能替代本链的字段与权限口径，页面协商详情还可能触发邀请/参与关系变化。不添加不存在的 `text=false` 等开关，不从历史数组猜测或要求用户手工提供内部轮次 ID。

页面的“打开/加入群”动作可能建群或拉人，本 Skill 只复用其群信息读取权限，不执行这些动作，不读取或总结飞书群消息。

## 输出与完成标准

展示实际返回的合同名称/编号、合同 ID、飞书群 ID 和群状态；不输出详情中的正文、文件、参与者明细。排障时可补充协商 ID、轮次 ID 和 trace，不能把它们混称为群 ID。

- 群存在且返回非空 ID：返回该 ID，并按实际状态说明机器人是否在群。
- 未建群：明确当前轮次尚未绑定群，查询到此完成，不自动建群；即使接口返回在群值 `false`，也不展示在群状态。
- 群已解散：说明已解散；有返回 ID 时标为历史绑定 ID，不承诺群可用。
- 状态未知、返回不完整或字段矛盾：保留已返回的事实，说明无法确认的部分；空 ID 不等同于未建群。

仅群存在、返回了可靠群 ID 且接口提供布尔值时，补充“接口报告当前用户在群/未在群”。缺失/null 保持未知，不填 false。

状态映射、缺失数组与失败处理统一按[接口与结果](references/api.md)执行。仅在同一用户上下文成功取得目标关联与当前轮次，并收到该轮次的业务成功响应后，才能报告这次群查询完成。

接口未注册、授权失效、无权限、业务错误或关联变化时，报告实际阻塞步骤。权限失败立即停止；不切换 app、账号、环境或其他接口绕过，不叠加自动重试。需要恢复授权时沿用认证技能的流程。
