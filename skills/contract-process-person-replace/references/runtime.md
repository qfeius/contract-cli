# 运行方式与边界

## 既有能力

复用当前已选择的 `contract-cli`，实际读取 `api call --help`、`auth status --help`，确认 web、USER、独立 query、JSON 输入及结构化输出。协议记录的是实际既有入口，不是新子命令。无需安装特定作者版本、其他业务 Skill、解释器或 JSON 工具。

页面请求入口为 `contract-cli api call --channel web --profile PROFILE --as user --output json`，之后使用接口协议中的方法、相对 path 和独立参数。PROFILE 取自本轮已核上下文，不让用户抄技术参数。

已有 `employee list` 可以按其原 Skill 得到公开目录候选，但它返回的 `user_id` 不能直接填入后台节点。本业务原生页面选人接口直接返回所需内部 `employeeId`，因此使用现有 web 调用器完成这段衔接，不要求安装人员 Skill，也不复制其开放 ID 契约。

## 身份与权限

`auth status --profile PROFILE --as user --output json` 的成功要求 `ok=true`，实际 profile、environment、identity 一致且 authorization 为 authorized。profile 名不证明实际环境，需采用本轮已核的公开端点/环境依据。复用当前 CLI 的授权续期，不读取凭据文件或索取 Token、Cookie、App Secret，不构造可信租户或用户覆盖头。

自身资料接口及交叉核对见 API 协议。身份核实后，先 GET 当前本人 `/open-web/web/clm/permission/function/list`，确认成功响应的 `data[].code` 实际包含 `admin`，再读取流程列表和本业务所需的其他人员资料。权限响应失败、结构未知或不含 `admin` 时停止流程枚举与后续动作；角色名称、系统管理员标记、页面截图或拥有其他操作项都不能代替这次本人权限核实。

角色页面的“合同流程管理”（`contract_flow_manage`）及发起补充协议、终止协议、修改表单和创建子合同子项，是合同实例操作权限，与本业务的后台“系统管理” `admin` 分开。具体 code 对照见 API 协议。流程列表、定义、edit、update、publish 与表达式生成仍由服务端检查当前组织 USER 的 `admin`；本人权限查询不取代这些接口的实际鉴权。首次列表被拒绝时保留拒绝结果，不读取流程或人员后再自行过滤。

普通 USER 的拒绝验收须使用已获授权且当前权限实际不含 `admin` 的 USER 会话；当前会话含 `admin` 时需另一个授权会话，没有时仅报告静态鉴权依据及负向未实测。不能修改角色、覆盖请求身份或切 APP 来模拟普通 USER。

人员页面接口在当前租户按名称或已知 ID 查询；只消费本业务需要的姓名、部门、状态、可选性和标识。批量 ID 回读只使用已获准流程中真实出现的人员，不枚举无关人员，不切其他租户。

## JSON 与文件

常规读取复用 CLI 的 `--output json`。本次所核入口直接返回 CLM 的根 `code/success/data`；授权命令的 `ok/data` 是另一种协议。宿主显示截断不代表响应内容为空；保存完整响应并继续读取本步相关对象。

只要求核实所消费字段、请求和回读的一致性，不对未使用的大型配置树承诺通用无损转换。当前结构化入口没有独立的原文重复键审计保证，不能声称它证明所有原始键唯一；发现重复键、同 ID 的冲突记录或矛盾状态时停止该对象。用户另要求原文级审计时说明具体缺口，不加解析/检测程序。

内部业务对象及人员标识（如 formId、tenantId、employeeId）保持原十进制字符串，不经 Number、浮点、科学计数法、算术或数字外观推导。node_id、processDefinitionKey、公开 user_id/userId 等按各自协议保持原不透明字符串，不强制十进制，也不与 employeeId 混用。服务返回不能可靠保留的数值 ID 时，停止依赖该标识的动作。全量请求中需要回传的嵌套标识也属于所消费字段，不能把可能已失真的数值当作未经处理的安全透传。`previousId` 可能是数值，不用它构造后续请求；版本处理使用交互规则里已核的有限分组方式。

宿主普通文件读写保存真实请求、响应和批次状态；这些是数据，不是脚本或新的业务配置语言。`processDefinitionJson` 是 JSON 字符串：读取内层对象、只改明确节点，再用标准 JSON 转义保存为字符串。宿主不能可靠完成时仅停止该流程，不自行写转换器、检测器、解析器或包外脚本。

POST 请求用 `--input-file` 承载已核原生 JSON；可用既有结构化参数安全承载时也可用 `--data`。不能把人员姓名等用户文本拼成可执行命令。GET 和本业务 publish 的参数均用独立 `--query`，不放进 path。

当前 CLI 请求体上限 1 MiB（1,048,576 字节）；以实际 UTF-8 请求文件字节为准，转义后内层字符串可能更大。请求超限时不得拆分全量保存、删模块、改默认值或绕过网关。说明此对象受阻，保留已确认输入和页面接续方案，其他流程继续。

## 批次状态与未知结果

使用宿主私有任务目录保存：profile/环境/租户/用户、完整扫描范围、人员身份、列表编号映射、源与目标 formId、节点 ID/规则位置、已确认前后值、编辑前快照、实际请求和 requestId、每个动作的发送与回读状态。不能把只有显示文本的表格当作可执行状态。

读请求错误沿用 CLI 自身恢复协议，不额外叠加重试。edit、update、publish 每阶段只发一次；未知结果先 GET 和列表只读核查。无法关联本次请求时仅报告已核的当前状态，不能以近似同名对象认领结果。不得自动删除疑似草稿、重建对象或重放整批来消除未知。

无 CAS/ETag/expectedVersion 证据；同一流程保存和发布有锁也不等于保护完整读改写周期。写前重读降低竞态，不能宣称原子防冲突或多流程事务。发现漂移保留已完成阶段，不擅自回滚其他操作者的修改。
