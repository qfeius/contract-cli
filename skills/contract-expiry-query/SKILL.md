# 合同到期筛选

支持四种查询：过去 X 天到期、未来 X 天到期，以及上述两种范围分别与“目前未归档”组合。X 天仅约束到期日期，不约束创建、签订或归档日期。不把“到期时未归档”的历史查询或独立的“过去 X 天未归档”解释为本功能。

## 确认条件

沿用本次对话已明确的时间方向、正整数 X、是否仅未归档和业务时区。未指定未归档条件时查所有归档情况；只有“未归档”而没有到期范围时，询问过去还是未来及天数。“最近到期”有方向歧义时先澄清；不默认 30 天。零、负数、小数或非数字天数需要用户修正。

过去和未来 X 天均默认包含今天，总共仍为 X 个自然日，不再询问是否包含今天。用户明确指定不含今天或具体起止日期时，以其明确要求为准；不能沿用旧对话中“不含今天”的默认口径覆盖本规则。业务时区沿用当前已确认上下文；尚不明确时只确认时区。按业务时区自然日计算，D 为本次实际执行时的当地日期，不沿用历史验收日；固定本轮基准日，不在翻页时重新计算：

- 默认包含今天：过去为 D−(X−1) 至 D；未来为 D 至 D＋(X−1)，共 X 个自然日。X=1 时两种查询均仅查今天；今天到期的合同可同时出现在过去和未来结果中。
- 用户明确要求不含今天时：过去为 D−X 至 D−1；未来为 D＋1 至 D＋X，共 X 个自然日。
- 业务时区只用于确定“今天”和起止日历日期。平台按 GMT+8 展示到期日；保持选定的年月日不变，分别按 GMT+8 的起日 00:00:00.000、止日 23:59:59.999 转成检索用 Unix 毫秒。不要把业务时区的零点直接发给接口。显示实际日期、业务时区和归档条件；跨月、跨年、闰日按日历计算。

不追加“仅归档中”“仅已签订”“仅我负责”等用户未指定的限制。默认范围是全部合同入口下当前用户可见的非草稿合同记录，保留平台原有合同组关系；不宣称租户全量，不擅自丢弃同组旧版本。对同组每条返回记录分别判断条件。

## 执行

调用前读取 [查询协议](references/query-api.md)，严格使用其中的字段、分页和失败规则。

1. 使用已有兼容的合同查询能力；必须与本协议具有相同日期、权限、归档字段及完整分页语义。不能确认等价时，使用已核实的 Open Web 查询路径。沿用当前通道选择；默认优先兼容 CLI，入口缺失或不兼容才考虑已连接 MCP，不因权限错误换通道。
2. 确认用户授权的生产查询范围、组织和 USER 身份；每条业务命令显式携带已核实的生产 profile，不切换到 app 身份。
3. 用到期日期闭区间取候选合同组。不要添加伪造的“未归档”枚举或“状态不等于已归档”条件。完整遍历候选页；用户仅要部分结果时可停止，但须明确未遍历完。
4. 对每条合同记录独立复核 `endDate` 在日期范围内，再按“目前未归档”条件判断；跨组以字符串 `contractId` 去重。不能把同组一条记录的到期日期与另一条的归档情况拼成命中。
5. 未归档判定：返回的 `archivedTime` 是有效非空时间时，已完成归档，组合查询排除（包括到期后补归档）；明确为 JSON `null` 且无冲突证据时，视为当前尚未完成归档。字段缺失、空字符串、零值、格式异常不当作 null；标记归档情况待核实。状态明确为“已归档”(9) 但时间为 null，或归档时间晚于本轮查询时点，均视为冲突，不计入确定的未归档结果。未知状态只保留原值，不凭名称猜归档事实。不用归档编号、扫描件是否存在代替归档完成。
6. 检索返回的是查询时读取的索引信息，并非事务快照。重复记录字段冲突、跨页数据变动或疑似索引滞后时说明不确定性；需最新强一致结果而现有能力不能证明时，说明限制，不断言无误。

## 输出与完成标准

先给出环境、用户可见范围、具体日期区间、时区、归档条件及查询时点。表格展示合同名称、编号、到期日期、当前合同状态、归档情况；必要时附归档完成时间。仅使用真实返回且可访问的详情链接，不拼造地址。不输出令牌或无关个人信息。

区分候选合同组数量、去重后日期匹配的合同记录数、确定未归档数量及待核实数量。接口的组总数不能当未归档合同总数。只有遍历完成且判定字段完整时才报告完整统计。保留内部字符串 ID 供去重与后续追问使用，无需默认展示。

完整查询无确定命中且无待核实项，才能说“该范围内未找到匹配合同”；有待核实项则单独说明；仅查了部分页时只能说“已扫描部分中未找到”。字段或某页失败不伪装为空结果。输出进度、已确认结果及未完成原因，不执行归档、改状态、发送提醒或其他写入。
