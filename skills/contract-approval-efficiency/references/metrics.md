# 统计口径与输出对账

## 任务、合同和时间

唯一任务键为 `(processInstanceId,processTaskInstanceId)`。读取 `done/todo` 全部记录，forecast不参与；重复副本去重，真实统计字段冲突的任务不计入汇总但保留诊断/明细。缺任务ID的行无法去重，保留原始行并排除汇总。

有效已处理任务须 `taskStatusCode in [1,2]` 且 `commandTypeCode in [1,2,10]`；分别为完成/拒绝及同意/拒绝/加签同意。拒绝由状态2或动作2识别，其余有效动作记通过；盖章、归档同意也用动作1。有效的起止时间、非负耗时和完成时间窗口都必须满足。其他动作、取消、自动跳过、异常时间另标原因保留明细，不混入效率均值。

`duration_seconds=endTime-createTime`。含等待、夜间、周末、节假日；不使用相对当前时刻的createTimeSpan/endTimeSpan，不是实际劳动时间。已处理按endTime半开窗口筛选；在途须status0、无结束时间、创建早于窗口end，是采集时状态，不还原历史积压。

| 指标 | 定义 |
|---|---|
| 处理合同数 | 本行有效已处理任务对应的 `(businessTypeCode,businessId)` 去重数 |
| 统计周期内涉及合同数 | 有效完成任务对应的 `(businessTypeCode,businessId)` 跨审批、盖章、归档去重数；具体人员模式只计入可唯一归因到所选人员的任务，不包含在途 |
| 审批通过次数 | 本行有效完成任务中同意/加签同意次数 |
| 审批拒绝次数 | 本行有效拒绝任务次数 |
| 总览在途合同数 | 本节点类型运行中任务对应业务键去重数 |
| 个人在途待办任务数 | 满足个人单人节点条件的运行中唯一任务数 |
| 总用时 | 本行有效已处理任务自然秒数之和；并行用时可重叠 |
| 平均用时 | 总用时 /（通过次数+拒绝次数），不除以合同数，也不平均个人均值 |
| 最长/最短用时 | 本行有效已处理任务时长最大/最小值 |

合同归属优先用record.businessId/businessTypeCode。只有record实例与外层实例相同才可补外层业务ID；历史实例缺自己的ID时不臆测归属。通过、拒绝次数可计有效任务，但未知合同不进入合同数，明细标“合同归属缺失”，因此两者不强求相等。名称/编号从同业务键的真实元数据精确关联，缺失留空。

## 人员清单和零行

bundle.employees必须是目标个人或部门的完整当前人员清单，即使没有合同或有效任务也保留。按employeeId匹配，姓名仅展示；默认每人在三个节点类型各有一行。记录外的零任务员工无法通过记录反推，缺人员清单时说明零行覆盖不足。空employees明确表示对象无成员，不应扩大到候选合同全部人员。

按用户要求：无有效已处理样本时，汇总的总/平均/最长/最短显示0（0.00小时），次数显示0；JSON同样为0。含义是当前有效样本为空，不是证明缺失记录的实际耗时为0。单条明细缺失/无效时间、尚未结束任务的完成时间和用时始终为空。未取得数据或排除导致的零值必须配合范围和诊断说明。

部门按当前组织快照，不还原历史。优先用一次完整目录快照一致补齐；没有快照而同一员工记录部门互相冲突时，部门聚合排除冲突人员并提示，人员/节点其他有效量不因此丢失。

## 个人效率与多人节点归因

1. 在筛选时间和动作前，先将发现阶段的原始 `task_records` 按 `(process_instance_id,task_instance_id)` 建立人员归因表，人员来自 `discovered_for_employee_ids`；再与流程记录的相同实例+任务ID连接。不能按合同ID、节点名或数组位置模糊关联。
2. 已办任务中心只归因到一个目标人员，且流程记录为有效人工完成/拒绝时，即使节点整体为会签、或签、串行或历史参与多人，也把该任务按自己的 `createTime/endTime` 计入该人员。待办任务中心明确属于目标人员时，计入该人员在途待办。多人节点本身不构成排除理由。
3. 或签未处理人的自动结束/自动终止记录，及取消、自动跳过等非人工有效动作，不计个人效率。任务中心仍对应多名人员的已办任务、与人员清单不一致、任务ID缺失或对账冲突时，保留明细并排除个人统计。
4. 没有原始任务清单的显式合同/流程查询，才回退完整历史人数证据：历史实例、定义、节点精准匹配，固定唯一人员且与可见记录一致。仅一个可见操作人或 `taskModeCode` 不足以证明单人。
5. 人数补证仍用于审计节点参与范围。历史固定定义配置多人而运行期只观察到一人时，配置人员保存在 `configured_employee_ids`，不能冒充实际处理人；原始个人任务存在时以任务归因为准，不存在时列单人条件待确认。

可选bundle.node_participant_evidence条目：

```json
{
  "processInstanceId": "有来源的历史实例ID",
  "processDefinitionId": "该实例真实定义ID",
  "nodeId": "真实节点ID",
  "employee_ids": ["该节点完整原始分配清单中的真实员工ID"],
  "complete": true,
  "source": "可复核的完整历史分配记录来源及覆盖依据"
}
```

这是没有原始个人任务时的回退证据入口，也用于核验节点参与范围；不能用当前流程设计或模式枚举代替历史事实。同任务ID存在节点、人员或操作冲突时不能生成完整证据。

总览仍计入所选对象范围内有效任务，每条一次。个人表报告任务中心已归因的多人节点任务数量，以及仍无法归因、单人条件待确认的数量。明细included_overview/included_personal明确两个统计分母，并保留personal_employee_ids。

## 明细与报告路由

统计周期和数据范围始终置顶。用户明确点名一人或多人时，analysis_subject=people，不显示总览、效率洞察和编号章节。目标人员清单只有一人时，审批/盖章/归档合为一张个人表并增加“节点类型”列；两人及以上仍按三个节点分表。部门、合同、流程或其他范围仍按“总览表及效率洞察 → 三个个人表 → 明细文件”输出。具体人员模式仍生成明细文件，并在个人表后以普通文件链接交付。

明细保留时间范围内可辨识的操作、在途快照、多人/未知单人/自动动作/异常时间等排除项，每条任务一行。缺完成时间等导致无法确认窗口的行保留并标记，不计汇总；明确窗口外完成记录不导出，但参与人数判断仍使用它们。冲突任务优先保留匹配对象及窗口的副本作为有冲突标记的明细代表行，选择不依赖输入顺序，冲突ID另列JSON，不采信该行做统计。

Excel先使用已有artifact-tool；失败或无依赖则写UTF-8 BOM CSV，给出原因及真实文件链接。ID以文本保存，CSV数字ID带文本前缀防精度丢失；导出无行数截断。不得用截图数据或合成夹具作为真实效率结果。

## 时区和覆盖

接口返回的无时区时间由请求Timezone-Offset=-480保证Asia/Shanghai，并需已有透传核验证据。首次环境试用无依据时不能标meta.timezone_confirmed=true。分析器拒绝未确认时区，保留原秒精度，最终显示小时两位。

候选分页不设默认数量/页数上限，重复页、游标缺失、权限/网络失败仍中止并报告缺口。不保证租户全量或全历史审计事件；目前历史或签人数的不完整尤其影响个人统计。平均耗时是任务平均，不能解释为并行节点整体周期。
