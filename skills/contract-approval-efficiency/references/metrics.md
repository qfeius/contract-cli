# 统计口径

## 唯一键与节点类型

任务唯一键为 `(processInstanceId, processTaskInstanceId)`。只有 `done` 和 `todo` 参与；`forecast` 不参与。

| 节点类型码 | 展示名称 |
|---|---|
| 1 | 审批 |
| 2 | 盖章 |
| 3 | 归档 |

未确认类型不归入三类统计，保留在诊断中。

## 有效完成任务

有效已处理任务同时满足：

- `taskStatusCode` 为完成或拒绝状态 `1/2`；
- `commandTypeCode` 为同意、拒绝或加签同意 `1/2/10`；
- `createTime`、`endTime` 有效且 `endTime >= createTime`；
- 完成时间位于 `[统计开始, 统计结束)`；
- 任务可以与人员和流程记录精确对账，没有关键字段冲突。

拒绝由状态 2 或动作 2 识别，其余有效动作记为通过。提交、撤回、取消、自动跳过、自动结束和其他系统动作不计处理效率，但保留明细及排除原因。

任务用时为 `endTime - createTime` 的自然时间，包括等待、夜间、周末和节假日。它不是实际劳动时间，也不是并行节点的整体周期。

## 人员归因

人员、部门和角色模式先用 `getVisibleTasks` 返回的 `(process_instance_id, task_instance_id)` 连接当前 USER 成功读取的流程记录。`discovered_for_employee_ids` 只表示哪些本次目标人员通过权限校验的查询流命中了任务。每个人的归因必须在其自己的命中清单中，不能用响应的 `assignee_ids` 或其他人的命中补齐：

- done 记录以 `process/records.assigneeEmployees` 为实际处理人依据；唯一实际处理人同时属于该任务的 `discovered_for_employee_ids` 且动作有效时，计入该人。
- todo 记录以 `process/records.assigneeEmployees` 为当前候选/经办人依据；每个同时属于该任务的 `discovered_for_employee_ids` 的目标人员计一条个人在途待办。
- 会签、或签和串行节点中，每个 done 人工任务按流程记录中的实际处理人及自己的进入和完成时间计入；候选人数多不构成排除原因。
- 或签中未处理候选人的自动结束任务不计。
- done 流程记录仍包含多个实际人员、人员不在目标清单、任务 ID 缺失或对账冲突时，排除个人统计。原始 `assignee_ids` 人数不能触发该排除。

合同/流程模式不依赖任务中心，直接按可读流程记录建立处理人清单。done 按唯一实际处理人归因，todo 按记录中的待办人归因，无需 `discovered_for_employee_ids`。人员/部门/角色模式中的历史证据只用于核对已通过新接口权限校验的候选，不得用于替代任务发现或补算被拒绝的员工。历史表单定义只有当前 USER 本身为管理员时可用。`taskModeCode`、当前流程设计或 `getVisibleTasks.assignee_ids` 都不能证明实际处理人。

## 时间窗口与在途

已处理任务按完成时间过滤。

统计周期的结束值不得晚于采集时刻。用户询问尚未结束的当前月或当前周时，以采集时刻作为半开区间结束值；本次报告不会自动包含采集后产生的任务。

在途定义为：**采集时仍处于待办，且进入时间早于统计周期结束时刻的任务子集。** 这不是统计周期结束时的历史积压快照；无法还原窗口结束后、采集前已经完成的任务。

只有当前 USER 成功读取 `process/records` 的实例才能进入在途。总览在途按合同业务键去重；个人在途按唯一待办任务计数。候选任务对应流程无权读取时标记覆盖缺口，不按零处理。

## 指标公式

| 指标 | 定义 |
|---|---|
| 处理合同数 | 本行有效已处理任务对应 `(businessTypeCode, businessId)` 去重数 |
| 统计周期内涉及合同数 | 有效完成任务对应业务键跨审批、盖章、归档去重数；具体人员模式只计能归因到所选人员的任务 |
| 审批通过次数 | 有效完成任务中同意或加签同意次数 |
| 审批拒绝次数 | 有效拒绝次数 |
| 在途合同数 | 本节点类型在途任务对应业务键去重数，仅用于总览 |
| 在途待办任务数 | 明确归因到个人的运行中唯一任务数 |
| 总用时 | 有效任务自然秒数之和；并行用时可以重叠 |
| 平均用时 | 总用时 ÷（通过次数 + 拒绝次数） |
| 最长/最短用时 | 本行有效已处理任务时长最大值/最小值 |

统计和结构化诊断保留原始秒数，报告表格和明细文件按以下规则展示中文时分秒：

1. 将最终指标四舍五入到整数秒；平均值先用原始总秒数完成除法，再对结果取整，不能先把每条任务换算或取整后再求平均。
2. 小时使用累计小时，不换算为天，避免改变统计口径。
3. 从高到低输出非零单位：`1小时52分30秒`、`31分15秒`、`20秒`。中间单位为零时可以省略，例如 `1小时20秒`；结果正好为零时固定显示 `0秒`。
4. 表头不再带 `(h)`，也不显示十进制小时。

无有效样本且数据完整时，次数显示 `0`、用时显示 `0秒`。数据未取得或覆盖不完整时用 `—`，不能用零代替。

任务列表元数据不能单独生成完成或在途指标。员工任务权限或流程读取缺口可能改变某节点指标时，受影响指标显示 `—`；只有适用权限校验后的记录完整且确实没有有效样本时才显示 `0` 或 `0秒`。

历史任务优先采用记录自身的 `businessId` 和 `businessTypeCode`。无法证明合同归属的有效任务可计通过/拒绝和用时，但不计合同数；合同名称和编号留空并标记“合同归属缺失”。

## 人员清单和空部门、空角色

人员、部门和角色模式的完整人员清单中，每个人都要在适用的个人表出现，即使三个节点都没有任务。合同/流程模式只列可读流程记录中发现的处理人和待办候选人，不应用部门或角色零行规则。

- `analysis_subject=department`、`roster_complete=true`、请求范围的目录人员确实为空：输出“该部门暂无成员”，次数为 `0`、用时为 `0秒`。权限拒绝造成的无可查成员按运行参考处理。
- `analysis_subject=role`、`roster_complete=true`、请求范围的角色名单确实为空：输出“该角色暂无成员”，次数为 `0`、用时为 `0秒`。
- `roster_complete=false` 或人员清单缺失：输出“未取得完整人员清单”，数值用 `—`，整体为 `partial`。
- 对象匹配与范围未解析按[发现规则](discovery.md)处理，不生成零效率。

部门和角色按采集时的成员快照，不还原历史调岗、离职归属或任务执行时使用的角色。

## 总览与个人口径

部门和角色范围的总览只统计流程记录中唯一实际处理人也通过本人对应的新接口查询流命中的有效 done 任务。todo 总览统计流程记录候选/经办人中至少有一名目标员工通过其对应查询流命中的可读任务，每个合同在对应节点只计一次；个人在途分别计入符合条件的目标候选人。

合同或流程范围的总览统计该可读流程内每个有效任务一次。个人表只计可唯一归因任务。因此存在无法归因任务时，个人合计可能小于范围总览，必须说明排除原因，但不要用自然等待时间评价员工表现。
