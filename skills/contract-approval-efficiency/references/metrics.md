# 统计口径

## 唯一键与节点类型

任务唯一键为 `(processInstanceId, processTaskInstanceId)`。只有 `done` 和 `todo` 参与；`forecast` 不参与。

| 节点类型码 | 展示名称 |
|---|---|
| 1 | 审批 |
| 2 | 盖章 |
| 3 | 归档 |

未确认类型不归入三类统计，保留在诊断中。

## 有效完成任务

有效已处理任务同时满足：

- `taskStatusCode` 为完成或拒绝状态 `1/2`；
- `commandTypeCode` 为同意、拒绝或加签同意 `1/2/10`；
- `createTime`、`endTime` 有效且 `endTime >= createTime`；
- 完成时间位于 `[统计开始, 统计结束)`；
- 任务可以与人员和流程记录精确对账，没有关键字段冲突。

拒绝由状态 2 或动作 2 识别，其余有效动作记为通过。提交、撤回、取消、自动跳过、自动结束和其他系统动作不计处理效率，但保留明细及排除原因。

任务用时为 `endTime - createTime` 的自然时间，包括等待、夜间、周末和节假日。它不是实际劳动时间，也不是并行节点的整体周期。

## 人员归因

先用任务中心的 `(process_instance_id, task_instance_id)` 连接流程记录，再读取 `discovered_for_employee_ids`：

- 已办任务唯一归属于一个目标人员且动作有效时，计入该人。
- 待办任务明确属于目标人员时，计入该人的在途待办。
- 会签、或签和串行节点中，每个实际完成的人工任务按自己的进入和完成时间计入处理人。
- 或签中未处理候选人的自动结束任务不计。
- 同一已办任务仍对应多人、人员不在目标清单、任务 ID 缺失或对账冲突时，排除个人统计。

没有原始任务中心记录时，仅可使用完整历史证据回退：历史实例、定义、节点完全一致，固定唯一人员且与可见流程记录一致。`taskModeCode`、当前流程设计或“只看到一个操作人”都不能单独证明历史唯一人员。

## 时间窗口与在途

已处理任务按完成时间过滤。

在途定义为：**采集时仍处于待办，且进入时间早于统计周期结束时刻的任务子集。** 这不是统计周期结束时的历史积压快照；无法还原窗口结束后、采集前已经完成的任务。

总览在途按合同业务键去重；个人在途按唯一待办任务计数。

## 指标公式

| 指标 | 定义 |
|---|---|
| 处理合同数 | 本行有效已处理任务对应 `(businessTypeCode, businessId)` 去重数 |
| 统计周期内涉及合同数 | 有效完成任务对应业务键跨审批、盖章、归档去重数；具体人员模式只计能归因到所选人员的任务 |
| 审批通过次数 | 有效完成任务中同意或加签同意次数 |
| 审批拒绝次数 | 有效拒绝次数 |
| 在途合同数 | 本节点类型在途任务对应业务键去重数，仅用于总览 |
| 在途待办任务数 | 明确归因到个人的运行中唯一任务数 |
| 总用时 | 有效任务自然秒数之和；并行用时可以重叠 |
| 平均用时 | 总用时 ÷（通过次数 + 拒绝次数） |
| 最长/最短用时 | 本行有效已处理任务时长最大值/最小值 |

统计时保留秒，展示小时保留两位小数。无有效样本且数据完整时，次数显示 `0`、用时显示 `0.00`。数据未取得或覆盖不完整时用 `—`，不能用零代替。

历史任务优先采用记录自身的 `businessId` 和 `businessTypeCode`。无法证明合同归属的有效任务可计通过/拒绝和用时，但不计合同数；合同名称和编号留空并标记“合同归属缺失”。

## 人员清单和空部门

完整人员清单中的每个人都要在适用的个人表出现，即使三个节点都没有任务。

- `analysis_subject=department`、`roster_complete=true`、`employees=[]`：输出“该部门暂无成员”，数值为 `0/0.00`，不扩大到候选合同中的其他人员。
- `roster_complete=false` 或人员清单缺失：输出“未取得完整人员清单”，数值用 `—`，整体为 `partial`。
- 姓名或部门对象未找到：状态为 `not_found`，不是空部门或零效率。

部门只反映采集时的当前组织快照，不还原历史调岗或离职归属。

## 总览与个人口径

总览统计范围内每个有效任务一次。个人表只计可归因任务。因此存在无法归因任务时，个人合计可能小于总览，必须说明排除原因，但不要用自然等待时间评价员工表现。
