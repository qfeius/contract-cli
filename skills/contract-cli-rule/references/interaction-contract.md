# 审批矩阵交互与组合操作契约

本文件补充多轮交互和现有结构化命令的组合操作。具体参数、字段类型和错误码以主 Skill 及参数文档为准。

## 连续对话

- 沿用同一对话中已确认的目标矩阵、业务用途、列结构、规则来源、写入策略和发布选择；只追问未解决的阻断项。
- 大段文本、文档或表格先完整解析并汇总问题，不按行重复追问；一次集中追问不超过三类高影响问题。
- 多个待确认计划并存时，用矩阵名称、动作、创建时间或 `plan_id` 区分；一个确认不能用于另一个计划。用户切换矩阵后，停止执行旧目标的计划并重新查询。

## 创建与定位

- 新建矩阵且用途未知时，确认用于审批路由、协商自动邀请还是维护或测试；已有矩阵的普通维护不重复追问用途。只有用户明确改为协商自动邀请时，才校验 `合同类型` COLLECTION 条件列。
- 创建时省略 `rule_table_id`，由服务端生成；不向用户索取或按名称推导。普通确认和成功回复不主动展示 Code；同名、多状态、排障、组合操作部分完成或用户明确查询时，展示返回的矩阵 ID 以便准确定位。
- `product_id`、`group_id` 先从已确认的业务上下文、profile、环境和权限确定；仍无法唯一确定时澄清业务范围，不猜测或切换目标。
- 创建前确认名称、用途、命中策略，以及规则内容无法确定的条件或结果类型。描述可选。
- 找不到矩阵时展示查询结果，只有用户明确要求创建才进入创建计划；同名、多状态或多个候选时展示名称、矩阵 ID、状态和发布版本，让用户选择。来源文件、计划和矩阵中的“第 2 行”无法唯一对应时，展示候选 `row_id` 和关键值。
- 列名重名或近似时展示 `column_id`、类型和现有配置，不按名称猜测列。

## 容量和输入来源

- 结构写入前按最终方案校验：优先级和备注固定占两列，总列数最多 12，条件列与结果列合计最多 10；已满时仍可更新现有列和规则行。
- 后端规则表最多 2000 行，默认空白行计入；`import plan` 完整分页读取现有行并按现有行数加计划 `create` 数预检，`update` 不增加行数。服务端 20302 仍处理执行期间容量变化。
- 对话文本、飞书文档、表格、Excel、CSV 和 Markdown 表格都只是规则来源；解析后按列头类型转换为 `import plan` 输入。已有规则内容直接解析，不强制用户套模板。
- 表格输入检查规则所在工作表或表格是否可唯一确定、表头是否为空或重复，以及隐藏行列、合并单元格、公式、说明行和汇总行；按问题类型与影响行汇总。字段不存在时，让用户选择映射、忽略或新增列；新增列单独确认，完成后重读列头并重新生成行计划。
- 人员、部门、角色或枚举值解析失败时，汇总无结果、重名和不可选项；按查询结果说明已离职、无权限可见等原因，展示候选，不猜 ID。

## 重复、更新和清空

- 重复导入不默认再次创建。按唯一 `row_id` 或已确认的匹配键识别已有行；无法判断时让用户选择追加、跳过或更新。`import plan` 只支持 `create` / `update`，跳过的来源行不进入新计划。
- “清空审批人”是将单元格设为空集合；“删除一个审批人”只移除该成员；“删除审批人列”是结构变更。表达不清时先确认。
- 显式 `null` 清空单元格，省略单元格表示不修改，集合 `[]` 清空集合，遵守导入参数文档。

## 计划、暂停与核验

- 矩阵定义、列结构、规则行、预发布和正式发布分别确认。结构变更完成后重读矩阵和列头，按新 `column_id` 生成并确认行计划。
- 用户只确认部分计划行时，用 `import apply --rows` 执行确认范围，其余保持 paused；取消后不继续执行，修改内容则生成新计划。
- 执行前核对 profile、环境、身份和矩阵；CLI 自动比较列头与全量行快照，发现外部增删改使计划失效。本计划已验证写入推进预期快照；并发窗口仍需后端 revision 条件写才能关闭。
- 导入计划的 24 小时有效期、部分执行和结果不确定时的恢复规则沿用主 Skill 及 `import get|pause|resume|verify|cancel`。
- 用户要求暂停时立即调用 `import pause --plan-id`；当前行写入与回读完成后不启动下一行。`get` 可查看 `pause_requested`，恢复时调用 `resume` 后再 `apply`。超时、断网、5xx 或进程中断后先查询副作用，不直接重试写请求。
- 401/403 不自动切换身份；429 停止后续写入。`import apply` 的写请求收到 HTTP 404/409/412 时，CLI 将计划记为 `invalidated`；先重新查询目标，再生成并确认新计划。其他错误的计划状态以实际输出为准。
- CLI 写入成功后先记 `unverified` 并回读；值吻合才记 `success`。回读失败或不符时返回 `needs_verification` 并停止后续写入，用 `import verify --plan-id` 只读重试；仍不符时报告差异和已完成部分，暂停发布。

## 组合能力

- 没有一键命令时，判断现有结构化命令能否组合完成目标；不回退 `api call`，也不因缺少同名命令直接断言目标不可完成。
- 组合操作记录每一步的目标、确认、返回 ID 和核验结果。中途失败时报告已完成和未完成部分，不把多步操作描述为原子操作。
- 直接命令和组合路径都不足时，说明可完成部分、缺失能力及其影响；页面操作仅在用户明确接受时作为后续方案。

### 完整复制矩阵与按可见信息重建

当前 `table get`、`column-headers list` 和 `row list` 无法完整回读列绑定、`symbol`、多选匹配、部门循环、`result_code`、默认值等配置，不能保证完整复制。用户要求“复制矩阵”或“其余一模一样”时，先说明缺口；只有用户明确接受“按可见信息重建新矩阵”，才执行以下流程。在接受前不创建目标矩阵；不得以可见字段一致宣称完整复制。

1. 查询源矩阵详情、列头和全部分页规则行，确认源矩阵唯一；汇总不可查询的配置，逐项补齐并请用户确认，不猜测列语义。
2. 展示目标名称、可重建的基础属性和发布选择，确认后创建目标矩阵。目标默认保持草稿；矩阵、列和行 ID 由服务端重新生成。
3. 新矩阵自带默认列和空白行。先将源列与目标默认列按类型和语义映射，确认可复用的列并就地配置；仅对缺少的列执行 `column add`，事先校验总列数。单独确认结构计划，完成后重读目标列头；失败时报告目标矩阵 ID 及已完成部分，不自动删除半成品。
4. 用 `row list --page-size 10` 唯一确认目标默认空白行及其 `row_id`。若行不存在、不唯一或已有业务值，停止生成行计划并重新核对。
5. 根据新 `column_id` 生成行写入计划：源矩阵首条业务规则用 `operation=update` 填入默认空白行，后续规则用 `operation=create`；`import plan` 不会自动复用默认行。展示计划并确认后执行 `import apply`。
6. 完成后查询源和目标，核对可见基础属性、列、业务规则行数和单元格值，确认无遗留空白行。行顺序、发布版本、重新生成的 ID 和不可查询配置如有差异，分别说明；结果称为重建，不称为完整复制。

### 复制行

- 同一矩阵内先读取源行，确认后用 `row create` 新增查询到的单元格内容；新 `row_id` 由服务端生成，默认追加，不承诺原位置或优先级。
- 跨矩阵仅在目标列语义经用户确认、且能建立明确的 `column_id` 映射时，复制可见单元格并回读核验；隐藏配置或列语义无法确认时停止，不宣称完整复制。复制可能产生重复规则，确认摘要中应说明。

## 发布恢复

- 正常预发布与正式发布遵守主 Skill 的全量规则行基准校验。
- 本地基准缺失且服务端为 `status=0`、存在 `prepared_version` 时，调用 `pre-release` 只读恢复；需完整双读版本和分页规则行，不修改矩阵内容。
- 收到 `baseline_recovered=true` 后，向用户说明“已重新核对并恢复发布校验状态，矩阵内容未修改”，展示 `prepared_version` 和 `row_count`，再次确认后才执行 `release`。不通过原值重写、清空、增删行或改列恢复状态。
