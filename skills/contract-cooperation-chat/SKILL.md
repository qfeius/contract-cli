# 创建协商群聊

处理一份合同的一项协商，使用当前登录用户在当前组织的身份。群属于协商的当前轮次。建群使用该轮协商人员，无需用户另列群成员。本 Skill 的业务范围由申请人和本轮有效协商参与人组成。后台对部分只有合同读取权限的用户也可能放行；本 Skill 在建群、入群前独立校验资格，只有读取权限的审批人或合同读者不能通过本 Skill 建群、加群。操作前核对当前环境、组织和账号。使用合同 CLI 时，按[CLI 调用说明](references/contract-cli.md)完成查询、提交与回查；使用 MCP 和合同页面时，按下文操作。

## 定位协商

- “第 5 个”等序号指用户刚看到的那份清单。取原行绑定的环境、组织和协商 ID，刷新该协商的当前轮次；不按重新排序的结果选行。清单不明确、序号越界或无法定位原行时，先请用户指定目标。
- “重新试一下”沿用上次已确定的协商 ID，重新查当前轮次、身份和群状态。上次提交结果不明时，先回查该次提交对应的轮次和群；不因重试而重放写入。重新查询本身也不表示同意加入已有群。
- 给出协商 ID 时，以字符串原样调用合同 MCP 的 `get_cooperation_detail(cooperation_id)`。保留长整型 ID 的全部数字。合同 ID 和轮次 ID 均不能代替协商 ID。
- 给出合同编号或名称时，调用 `search_cooperations`，将原文传给 `keyword`，每页最多 20 条，按响应的 `page_token` 原样续页。该搜索也匹配人员姓名，须核对合同编号或合同名称。仅在全部候选中有唯一精确匹配时自动选定。只有近似匹配、同名合同或同一合同有多个协商时，列出候选的合同名称、编号、协商 ID 和状态，让用户选一项。翻页失败或令牌重复时先说明查询不完整，避免误选。未标注的数字串若可能同时指编号和协商 ID，先消歧。
- 优先复用同一用户的最新匹配行。只有协商 ID 或列表缺少必要信息时，使用同环境、同组织、同一用户的只读 MCP 详情，核对 `cooperation_id`、`contract_number` 和目标合同，取 `cooperation_round_id` 作为当前轮次。无可见匹配、详情无权读取和请求失败分别说明；这三种结果都不足以判定用户不在协商中。

## 读取当前轮次的群状态

用同一用户的最新列表行或只读 MCP 详情确定当前轮次。群查询不主动打开协商详情页，不调用页面详情接口补字段；进入详情在某些情形下可能改变邀请或参与关系。

- 对一个已确定的当前轮次调用 `POST /clm/api/cooperation/chatGroupStatus`，请求体为 `{"cooperationRoundIds":["<当前轮次ID>"]}`。从业务成功响应取 `data.cooperationChatGroupStatusList[0]`；`EXIST_WITH_ROBOT`、`EXIST_WITHOUT_ROBOT` 表示已有群，`UNEXIST` 表示无群，`DISMISSED` 表示原群已解散。状态为 `UNKNOWN`、业务失败或状态缺失时，报告无法核实群状态，停止操作。
- 已有群时先查 `data.membershipQueryFailedRoundIds`：若包含当前轮次 ID（按字符串比较），即使成员标志为 false 或 true，也按“成员身份未知”处理——仅提示“协商群已存在，暂时无法确认您是否在群内”，不询问、不提交入群。排除该失败后，仅接受 `data.currentUserInChatGroups[0]` 的布尔值；缺失、非布尔值或冲突按未知处理。若目标环境未返回 `membershipQueryFailedRoundIds`，再按“false 表示接口报告未找到本人”处理，并说明该环境缺少失败标志。
- 从同次响应的 `data.openChatIds[0]` 取飞书群 ID，供确认前后核对。可重新读取该轮群状态；始终缺少 ID 时暂停入群。已有授权页面中，协商详情的“打开协商群”只能证明群存在；本轮正文预览中的“加入协商群”按“接口报告未找到本人”处理。不要点击按钮来试探成员身份。

## 判断当前用户的协商资格

需要建群或加入已有群时，可按 CLI 说明复用最新列表行的本人参与标志、角色和有效状态，三者联合判断。使用 MCP 时，将同组织当前登录用户的可信 `user_id` 与详情本轮有效人员 `cooperation_users[].employee.user_id` 核对。发起者（`cooperation_user_type_code=0`）或协商者（`=1`）任一命中即可；在页面可用当前账号的唯一员工身份核对本轮“合同申请人”或参与人卡片。排除历史轮次、已退出、被移出及失效记录。合同读取权限、审批角色和同名人员都不足以证明资格。账号标识无法对应或名单不完整时，说明“无法核实当前账号的协商身份”，停止写入。

## 处理建群请求

| 当前轮次群状态 | 当前用户 | 处理 |
|---|---|---|
| 已有群，本人已在群 | 无需再查协商角色 | 回复“协商群已存在。”有已核实的群 ID 时附飞书直达链接。 |
| 已有群，接口报告未找到本人 | 有效申请人或参与人，群支持加入 | 先记下当前账号、组织、协商 ID、轮次 ID 和飞书群 ID，再询问“协商群已存在，系统未查到您在群内。要帮您加入吗？”群 ID 无法核实时说明原因，暂停入群。 |
| 已有群，接口报告未找到本人 | 已确认既非申请人也非参与人 | 回复“您不在当前合同协商中，无法加入协商群。”结束。 |
| 已有群，接口报告未找到本人 | 有效申请人或参与人，但机器人已被移除 | 回复“协商群已存在，但群机器人已被移除，暂时无法通过系统加入。请联系申请人协助。” |
| 无群或原群已解散 | 已确认既非申请人也非参与人 | 回复“您不在当前合同协商中，无法创建。” |
| 无群或原群已解散 | 有效申请人或参与人 | 刷新确认仍为同一轮次、本人仍有资格、群仍可新建，再通过已选 CLI 或页面的“新建协商群”提交一次。若刷新时已有群，改走上方已有群分支；若轮次已变，从新轮次重新判断。 |

页面仅在协商人员超过一人等条件满足时展示“新建协商群”。入口缺失或不可用时，报告页面给出的原因；原因未知则说明当前无法通过该页面建群。

## 收到入群答复后

“建群”的原请求不视作同意加入已有群。只有对上一条具体邀请的明确答复才可继续。拒绝、未答复或答复含糊时不提交。

1. 用发起询问时的账号重新读取协商与当前轮次。核对组织、账号、协商 ID、轮次 ID，以及询问时记录的飞书群 ID。轮次或群发生变化时，原同意失效；说明变化，并按新目标的实际状态重新判断，符合入群条件才重新询问。原群已解散时结束此次入群操作。任何一侧缺群 ID、返回结果冲突或无法核实同一群时，暂停写入。
2. 对同一群重新核实成员状态。本人已在群就回复“协商群已存在”并附入口。接口仍报告未找到本人且无明确失败时，重新核实当前轮次的协商资格和机器人状态，按上表处理。
3. 仍符合入群条件时，通过已选 CLI 或本轮合同正文预览的“加入协商群”提交一次。用户已在对话中明确同意，可完成页面的入群确认。仅加入当前用户本人。

## 核对执行结果

提交后刷新同一轮次。建群前明确无群、提交成功且回读确认本轮已关联返回的群，可报告“协商群已创建”；确认仍是用户同意的原群且成员标志可靠为真，可报告“您已加入协商群”，并附直达链接。回执分别陈述建群结果和已核实的成员情况；创建成功只能证明群已建立，不能据此声称所有参与人或外部协商方均已入群。出现超时、对象变化或证据不足时先只读回查，报告可确定的群及成员状态，不自动重放请求。若只能查询，或必须先进入可能改变参与关系的页面才能校验资格，说明哪一步未执行。

合同 CLI 与页面的建群和入群最终复用 `openOrCreateChatGroup`，由服务端按提交瞬间的群状态选择操作。写前刷新可以发现部分状态变化，但并发情况下仍可能发生“拟建群时加入已有群”或“拟入群时原群已解散并被重建”。如发现目标或实际动作发生变化，按实际结果告知用户，不把变化算作原请求执行成功。

### 群名和飞书直达链接

1. 对新建成功、已在群内及同意后加入成功三种结果，回读目标群的当前轮次，取群状态响应中的 `data.openChatIds[0]` 作为飞书群 ID（`openChatId`）。若该字段为空，可只读刷新同一轮次的群状态；仍缺失时省略链接。如建群响应也返回了群 ID，应核对二者一致。ID 冲突时先刷新核实，仍有冲突则省略链接。合同编号、协商 ID、轮次 ID 和内部 `chatGroupIds[0]` 均不可用作飞书群 ID。
2. 如果建群后飞书已打开该群，可读取对应会话的群标题。也可在同一组织、同一用户的已授权飞书 CLI 上运行 `lark-cli im chats get --as user --chat-id '<openChatId>' --format json`，将占位符替换为核实的群 ID。成功时取 `data.name` 原文作群名，并按纯文本展示。合同标题和群命名规则仅供识别合同，不能据此补写群名。
3. 复用合同页面的飞书直达链接 `https://applink.feishu.cn/client/chat/open?openChatId=<编码后的群ID>`。仅对实际 `openChatId` 做 URL 查询参数编码，回执中将完整 HTTPS 地址渲染为可点击的 **打开飞书群聊**。这个入口用于打开指定群，无需生成邀请链接。

新建成功的回执用一句话给出结果，例如「协商群『采购履约协商』已创建。」随后附上“打开飞书群聊”链接。群名以实际读取结果为准。飞书账号与群分属不同组织时，群名可能读取失败。若只取得群 ID，回复「协商群已创建，暂未读到群名称。」并照常附直达链接；若只核实到群名，则展示群名并说明「暂未取得群链接」。两项均缺失时如实说明，保留已核实的创建结果，不再次建群。

取得有效群链接但飞书报账号跨租户时，附上链接并提示“请用合同所属组织的飞书账号打开”。仅展示已核实的群名；群名或链接读取失败不触发建群或入群。
