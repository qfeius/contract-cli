# 完成协商+提交审批

用户可按合同名、编号、已有获权链接、上传后已生成的合同或筛选条件定位。复用本人草稿和「我的协商」查询；只对已定位、有真实上传正文、且当前个人身份可办理的合同启用表单送审。模板生成正文的对象排除。仅有文件、模板或协商 ID 时不能当合同 ID；有文件但尚未形成草稿，说明需要已有的建草稿能力。组和成员使用各自资格与协议，不能拆用独立单合同请求。独立多合同按实际 ID 去重，逐份维护表单和确认；仅对已确认的对象执行。

## 1. 定位与核实送审资格

依次读取[会话与调用上下文](references/runtime.md)、[定位协议](references/discovery.md)。使用当前 USER 权限。同名或对象类型不明时请用户选真实候选。先核实际正文来源、状态、角色及对应页面动作。

- 用户明确要求填写并保存、保存后回查或只验收字段时，走[独立保存](references/field-save.md)。按实际正式合同表单权限办理，包括表单二合一处于协商中的合同。保存请求在字段回查结束，协商清洁、倒签和审批属于其他业务动作。
- 非二合一协商中，原页面有独立前置表单时，按[协商前置表单](references/cooperation-preform.md)确认当前发起人、实际表单及个人通道适配，再引导填写和保存回查。用该入口返回的字段和联动规则构建工作表。
- 用户要求送审普通草稿或已完成协商的合同时，核当前提交入口和审批实例后按[普通送审](references/submit.md)处理。协商完成后从独立申请页首次送审的原生文件上传合同，按[普通送审文件准备](references/ordinary-file-preparation.md)判断是否复用已核清洁版或准备本次变更文件。已有实例先回查。重提须另核当前任务与对应协议。
- 本次动作需要完成协商时，按[协商完成前置](references/cooperation-submit.md#1-核适用动作和清洁方式)核实际模式、当前轮、当前用户权限及服务端清洁生效值。表单二合一与普通协商共用此检查。明确未开启时提示用户去原协商页面办理。结果未知时先核实。

## 2. 展示原表单并接收修改

按[表单协议](references/form.md)读取当前实际可见的标准、自定义字段及候选。用户提出提交审批时，直接展示[待填写表单](references/form.md#对话内表单展示)。顶部给出全部可见字段数量、必填进度和本轮待处理项。按原页面分组逐字段展示当前值、必填、填写状态及选项。把自动提取结果标为待确认，用户可集中采纳或点名修改。已采纳值立即进入本轮表单。

用本轮值依照已有系统规则重算。更新总数和必填进度，集中展示变化、仍待填写的必填、失效的选项以及需要确认的派生值。保持其他有效值。初始提取结果和修改前的当前值用于比较。仅保存按[独立保存](references/field-save.md)确认目标字段，按用户要求逐项或合并保存。送审按完整表单及动作的最终确认执行。

默认用聊天中的分组表格呈现，用户可按「字段名=值」批量回复。宿主已提供并核实能承接这些字段和回执的表单控件时，可将相同字段视图交给宿主，并核对回传的对象和版本。不能要求用户填写技术 ID、凭证或 JSON。收到表单回执只代表取得输入。

## 3. 两次确认与提交前置

按[表单的就绪规则](references/form.md#联动复算与就绪判断)确定可进入确认后，提示用户下一步。用户选择送审时，展示当前这份合同的**完整拟提交表单**，包括选填空值及当前适用条件项。普通送审收取针对这一版的「确认提交」。表单二合一展示「完成协商并提交审批」，提示本轮结束后协作方将无法继续参与，收取针对本合同、本轮和本版完整表单的确认。原页面实际要求先编辑签章位置时，按对应真实动作确认。用户返回修改就回到表单步骤，存在缺项或规则未核时指出具体原因。

确认后按[提交、倒签与回查](references/submit.md)取当前日期、有效配置和前置校验。需要倒签时展示风险及合法原因，按真实配置收集说明或材料，将补充内容纳入完整表单再确认。普通送审按当前提交协议继续。需要结束协商时按[服务端办理协议](references/cooperation-submit.md#3-通过接口完成协商)传已经核实的服务端清洁生效值，使用当前轮最新已保存正文。纸质二合一首次送审按[分段回查](references/cooperation-submit.md#4-分段回查与恢复)核实本轮最终版和正式正文绑定，再根据审批实例决定衔接动作。反馈「已发起」须有本次同一合同的实际流程证据。

## 4. 未适配条件与恢复

完整运行态表单、动态规则、倒签、正文保存或写入链有任一必需能力未核实时，继续处理当前授权内可验证的步骤，说明具体待核事实。原协商页面仅作为用户自行办理的入口。接口异常或用户在原页面操作后，按[分段回查](references/cooperation-submit.md#4-分段回查与恢复)接续，沿用仍适用的已确认数据及动作。

恢复时沿用已定位对象和用户提供的输入，重新核实身份、合同版本、规则及状态。发生变化的字段需重新确认。已经发送但结果不明的请求，先回查本合同的字段、状态或流程，保留「结果待核实」；未经核实不重放。
