# 非二合一协商的前置表单

在当前个人 Web 通道读取、填写、保存并回查原生协商前置表单。按当前对象及部署复核读取范围、字段编辑权限和适用的保存协议。

## 确认对象和可编辑范围

- 复用[本人协商定位](discovery.md#我的协商)与[运行上下文](runtime.md)。适用于当前发起人办理的文件上传类普通单合同，当前轮为草拟阶段、协商中（`cooperationStageCode=0`、`cooperationStatusCode=2`），原生协商详情明确 `enableFormCooperation=false`、`cooperationWithPreForm=true`。核当前 USER 的租户与员工等于同一轮的发起租户及发起人。仅能查看的参与者可以在各自已核授权内查看，保存适用当前发起人原页实际可编辑的字段。模板填空、合同组、待发起、审批中和重提走各自协议。
- `cooperationWithPreForm` 来自实际合同表单配置和本轮匹配的前置字段。确认页面有有效字段及可编辑控件。字段权限采用 `processAttributePermission.attributePermissions`；页面在该权限数据缺省时回落到 `nodeConfigMap["UserTask_submit_0:0"].attributePermissions`。用当前字段、组显隐和控件规则继续判断可编辑性。只有公告或空模块时，如实说明。服务端清洁取值仅用于完成协商。
- 记录当前 `cooperationId`、`cooperationRoundId`、业务合同 ID、表单 ID、权限和基线字段快照。写前重读。发现对象、轮次、表单、权限、当前值或生效规则变化时，按变化重新核算与确认。

## 读取和填写

使用当前个人的[通用 Web 通道](runtime.md)。只有已核目标和读取影响适用时，调用 `GET /open-web/web/clm/cooperation/queryPreCooperationModuleInfos`，query 仅传实际 `cooperationId`，无 body。该 GET 依据当前轮成员或已核协商查看权返回前置表单。后台可能读取交易方、采购数据和外部企业信息，核对本次权限和页面等价读取影响。原页面编辑组件初始化会触发表单保存，单纯取数使用已核读取入口。

- 采用 `code=200`、`success=true` 的 `data`。核对 `contractId` 等于同轮业务合同 ID，`formId` 等于该合同当前表单绑定。用返回的 `moduleInfos`、组、字段配置和权限判定本轮实际表单；将其与同一响应的标准值、`schemaValueMap`、`presetSchemaValueMap` 和 `tableValueMap` 按稳定字段键对齐。表单或完整字段缺失时，区分无可用前置表单、无权限和读取结果不明。
- 复用[对话表单、联动复算及确认](form.md)。展示字段要求、已填值、空值、实际备选项和只读状态。用户可一起回复多项。只对确认的值更新工作表。动态人员、部门、主体等按当前合同和字段权限取真实候选；未能核对的选项、关键联动及写法保留待核实。
- 改动上游选项后，复算显隐、必填、可选范围、计算值和受影响字段，保留其余有效值。未展示、隐藏或未加载的非目标值沿用实际保存协议。需要调整协商人员时，按下节说明影响。

## 保存请求和联动

当前原生编辑入口为 `PUT /open-web/web/clm/cooperation/contract/update`，query 为实际 `cooperationId`，body 为页面的 `ContractUpdateDTO`。先核对明确保存授权、同轮与当前字段编辑资格、写入映射及可预见的影响。在目标对象的个人通道写权限和映射尚未核时，继续提供已核的读取与填写引导。

| 请求内容 | 组装依据 |
| --- | --- |
| `contractId`、`formId` | 取本轮已核前置表单回读的实际绑定，与当前协商对象一致。ID 保留原文。 |
| 标准字段组和日期 | 只将确认的变更合入页面 DTO；保留实际 `payType`、`contractPropertyTypeCode`、`fixedValidity`、`fixedValidityDetail` 及与之适用的金额组合、币种和日期。金额写为 `{amount,currency}` 对象，保留精确值。接口会为缺失的枚举字段填默认值，缺失的说明等字段可能被清空。按页面规则传相关期限、原有部门、说明、签约及其他受管值。[标准字段映射](field-save.md#组装请求)供已核同形字段复用。非二合一且合同在协商中时，此入参的合同名称不落库。 |
| 自定义、预置及表格值 | 用当前对象的 `schemaValueMap`、`presetSchemaValueMap`、`tableValueMap`、`nodeConfigMap`。既有键同名时，服务合并以预置映射为准，按真实键归属更新。字段类型和多选、数值或人员映射参考[字段取值](field-save.md#字段取值)。按控件实际规则保留非目标键、合法 0 或 false。用户指定清空时核该字段的有效空值含义。 |
| 主体、采购、预算、项目、附件和专项控件 | 有独立存储、计算或回填协议时按原控件处理。只在可核当前适用协议且已授权时执行。整体更新体采用当前已确认的 DTO 投影，省略原页面剥离的 UI 字段。例如项目按原页独立映射，常规字段保存不从详情透传项目记录或改写 `contract_projects`。 |

对可能影响协商人员的字段，先核角色匹配、部门及国家地区联动。原页面填齐后可能计算增减人员，计算也可能保存匹配计划及调用外部服务；更新承办人、应用协商人员增减会改变人员关系或发送通知。需要对应的影响证据与授权，再按实际页面独立动作继续。仅保存的授权止于明确可执行的字段写入和回读。必要联动尚未核实时，先停在受影响字段的写入前。

归属部门采用当前申请人可选的实际部门 ID，写根字段 `departmentId`。当本轮启用按国家或地区分配法务且挂载了相应控件时，页面用 `GET /open-web/web/clm/country/findCountryByName` 的 `name` query 读取候选，按实际 `countryCode` 和 `countryName` 对齐，选中值数组写到本轮配置的 `schemaValueMap` 国家地区字段。该字段采用上段的人员联动规则。

## 回查与停止点

1. 按确认内容发送一次。要求 `code=200`、`success=true` 及正常的更新结果对象。结果对象为空、超时、拒绝或响应中断时，先按同一协商和轮次重读现状。
2. 重新读取同一前置表单并核同一版本及当前轮，按字段类型比对目标值、非目标保存值和派生变化。需要验证状态时复用实际协商状态与基础合同回查。只有值一致且对应同一对象，才报告已保存。仅保存时，应回查仍在协商中、审批实例与基线一致。
3. 缺权限、未落库或结果未知时报告已核步骤，先处理具体阻塞。前置表单填齐后，如用户另外授权完成协商，按[协商完成前置](cooperation-submit.md#1-核适用动作和清洁方式)检查同轮及灰度，继续对应动作。独立送审重新读取完成后的正式申请表单并确认。
