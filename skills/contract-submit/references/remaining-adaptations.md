# 本期交付与页面办理边界

本期只使用现有且适配当前身份的能力，完成查询、定位、状态/权限解释和原生页面链接编排。系统原有能力或接口字段不足，不列为本期研发、发布依赖或全包阻塞，也不以不安全查询、猜字段或代办绕过。

## 按现有能力交付

| 情形 | 本期实际处理 |
| --- | --- |
| 本人普通、模板和父组草稿 | 使用本人范围查询及对应原生页面；普通草稿的模板分流只在所需事实齐备时执行。独立协商已完成时使用完成态入口，不因合同31重新套草稿模板判据 |
| MY 协商定位 | 支持当前授权参与范围的列表、筛选和定位；历史关联不冒充当前轮成员。严格窄详情及必要身份补证按[查询协议](query-protocol.md)执行，失败时保留已获权协商承载页 |
| 完成态二合一事实已明确 | 非二合一普通/模板单合同进 `/apply/edit`；二合一用原协商表单；角色、合同状态及任务资格仍须满足[权限边界](permissions.md) |
| 完成态已取得真实当前页面操作目标 | 按[系统页面入口](native-page-handoff.md#协商完成入口)校验并复用，不重复索取已不影响选页的对象字段；有地址不等于有权限 |
| 没有可信动作目标且对象模式未知 | 按[查询协议第8节](query-protocol.md#8-协商完成后的页面配置查询)判断受限页面读取条件，满足时取得对象模式并交付准确提交表单；不因为窄接口缺字段直接降为协商页 |
| 页面读取条件不满足、用户仅允许纯读、查询失败，或操作资格无法确定 | 保留已获权协商页，分别说明未确认原因，不把该链接称为直达提交表单；不为此修改CLI或后端 |
| 父组10/17 | 保留父组草稿及拒绝/撤回重提入口。当前正常父组流程没有整组协商链，不新增“父组协商完成后提交”分支 |
| 成员协商、历史或特殊父子关系 | 有真实关系时按已核父级办理依据处理；关系不明时给已有获权协商/对象页并说明，不能把成员完成当整组完成，不能凭类型0判独立合同 |
| 非本人草稿、MY范围外的对象 | 可复用本轮已有可信获权精确对象、任务或原生入口；当前查询未覆盖时明确范围，不枚举全租户，不报告系统中不存在 |
| 撤回/拒绝重提 | 复用或查到本人当前待办后核 task/info 及对应操作入口；缺当前任务事实时给获权承载页，不伪造任务、不调用有副作用 composition |
| 作废、履约确认、到期提醒 | 仅使用已核原生详情/任务承载页，明确用户还需点页内动作；不制造直达弹窗 URL，不把提醒当履约完成 |
| 未有本包可执行路由的特殊类型 | 复用本轮已有可信具体入口；否则给获权对象查看页或说明暂无法定位。不从枚举、相似路径或其他合同借用参数 |
| APP上下文 | 不执行本包未建立安全协议的对象查询。可复用本轮已有可信获权快照输出查看入口；没有快照则说明目前无法代查定位，不切USER、不把应用可读当个人可提交 |
| 未有页面映射的环境或客户端 | 只用已核真实 HTTPS 基址及适用页面。未知站点不替换域名猜路径；宿主能打开链接不等于所有移动页面可操作 |

上述情形的准确路径与参数维护在[系统页面入口](native-page-handoff.md)及[场景覆盖](scenario-actions.md)。仅有承载页就如实交付承载页，不将它改名为“提交审批”来掩盖一步直达未确认。

完成态须区分两条能力：现有纯读窄查询不返回对象二合一标记；现有页面详情可以返回，但包含原页面的浏览附带行为。本期在第8节明确的授权和前置条件下复用后一能力，不要求新增后端接口。不能在仅获纯读授权时偷换为页面等价读取，也不能把页面读取推广给未核实的非成员、其他轮次或父组。两类既有依据都没有、且该受限查询也无法采用时，才仍有直达选页缺口。

## 查询或页面事实不足时

逐项输出真实对象、已知状态、未确认的业务条件和已有获权入口；没有入口时说明暂无法定位。已有确定结果继续交付，失败项保留在原清单中。名称重名可询问用户选择真实候选；内部字段、Token、接口选择不能转交用户补齐。

briefInfo 为 null、严格详情拒绝/UNKNOWN、跨租户限制、请求失败和分页不完整分别解释。它们不能互相代换为“合同不存在”或“用户无权限”。严格预检失败时不降级到页面详情；页面配置仅按第8节受限使用，不用它包装成纯读，不调用保存或提交准备补结果。

## 完成标准与结果强度

本包完成点是支持范围内的对象可按现有能力定位，操作标签与证据一致，真实链接和非直达情形说明清楚。用户在页面实际保存、完成协商或提交审批，是后续页面操作，不是生成链接的完成证据。

文件检查、离线演练、打包与安装分别只证明相应产物；不能写成当前部署的所有真实合同均已验证。真实接口、页面打开及完整提交是否通过，只报告当次实际完成的验证范围。用户说已操作后，按其要求安全回查当前状态；没有已核回传机制，不承诺自动返回聊天或持续监控。

登录会话、宿主打开方式和自动回传边界统一见[平台限制](platform-limits.md)。不因这些已明确边界重复要求用户选择交互方式。
