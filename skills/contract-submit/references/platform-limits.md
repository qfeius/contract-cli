# 链接办理的实际边界

| 事项 | 可承诺的行为 |
| --- | --- |
| Codex、豆包的文字链接 | 提供真实 HTTPS 系统地址；宿主决定在内置页、新标签页还是系统浏览器打开。不能保证所有客户端都展示原生按钮或强制外部浏览器 |
| 页面样式、字段联动与必填 | 使用原合同操作页面，本 Skill 不复制表单，因此规则由页面当前版本执行；是否能提交仍以该对象的校验结果为准 |
| 登录、企业与身份 | 原页面使用浏览器会话，可能需要登录或切到正确企业；与 CLI 不自动共享登录态。无凭据 URL 不提供免登录承诺 |
| 提交后回到聊天 | 没有已核的原生页面回调或自动唤醒协议；用户告知已处理或要求刷新时再只读回查，不能承诺自动跳回、自动更新或一直监控 |
| 陈旧状态与链接 | 入口是核实当时的快照，后续可能被其他人修改；由页面再次鉴权，回查后更新聊天结果，不能让旧链接绕过最新规则 |
| 企业定制域名、入口与移动端 | 只采用当前已核站点和适用页面路由；PC 链接不等于每个移动客户端可操作。缺映射/路由时具体说明，不拼类似地址 |
| APP 查询身份 | 可读不代表浏览器个人可提交。APP 不提供 USER 本人草稿查询，也不把个人写权限从应用授权推导出来 |
| 系统页面只有弹窗操作 | 可给真实详情页或任务页，说明还需点击的具体动作；不虚构直达弹窗参数，不把两步操作描述为已进入填写页 |

这些是宿主、登录或现有页面交互边界。尚未核实的业务路由和页面验收是[Skill 适配边界](remaining-adaptations.md)，不能笼统说系统不支持。旧版集中表单、Cube 调用和 APP 自动提交的限制不再作为本包运行前置；这些工作由用户打开的系统页面处理。
