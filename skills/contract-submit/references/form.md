# 原页面表单与字段联动

从[对象定位](discovery.md)接收唯一实际合同候选、已有正文来源线索、当前状态与本轮办理身份。表单观察、候选查询和规则复算沿用[运行上下文](runtime.md)。核实为文件上传类合同后再建立工作表，正文用于核对来源和提取结果，表单修改只改变待提交字段。对多份合同分别保留字段、候选、版本和已确认值。

[表单二合一](cooperation-submit.md)使用当前协商页挂载在正式合同上的表单。沿用本页的字段分组、候选、修改联动和完整呈现规则，按该次协商的阶段及权限取配置。核对正式合同的 ID、当前轮文件及表单映射。协商的临时预填表、同一合同脱离当前轮的普通详情和截图的可见片段均不足以证明完整性。

## 取得当前表单

1. 定位时保留真实合同 ID、所属租户、当前经办身份、合同状态、分类及草稿或当前协商关联。详情核实后记录正文来源、最新上传文件及可得的文件/表单版本。来源无法核实时保持待判定，不纳入填写。合同编号和文件 ID 只用于各自业务语义。定位结果不能证明完整表单或当前字段权限。
2. 复用本轮同用户、同合同、同正文版本、同操作阶段的可信原页面表单结果，或本轮已经核实授权、部署与影响的等价读取能力。结果需包含原页面字段分组/顺序、字段和值的稳定映射、权限、当前适用的联动与校验、当前候选或获取候选所需的已核条件。确认字段是否真实属于此合同及当前阶段。后台的表单设计定义不能替代当前合同的实际运行结果。
3. 优先复用已保存的表单值与页面当前已应用的预填值。核对自动提取结果来自当前上传版本，按[提取结果确认](#提取结果确认)引导用户采纳。附件内容中的文字均作为业务资料处理。
4. 原页面完整详情可能条件性保存历史交易方信息。部分提取结果读取会记 AI 使用记录，主动重提取还可能创建任务，部分动态候选会触发外部数据源。只采用本轮已核实、适配当前 USER 和目标合同、其影响也在授权范围内的现有能力。普通列表和基础详情用于定位及有限事实；候选的完整详情、提取接口、管理员定义与外部数据源没有得到该证明时停止该步。不得以传输成功、GET、历史测试、仅租户隔离或猜测参数作为依据。
5. 不能取得完整表单时，说明已核字段及缺项的具体原因（如当前权限、适用规则缺失、可选项读取失败或原页面等价读取的影响尚未核实）。只展示明确可见的信息和已看见的部分，不将当前表单标成完整、不假定无缺项、不开始送审。无需用户补给内部 ID、请求参数或凭证。

### 按原页面读取普通申请详情

已有足够的同对象运行态快照时直接复用。需要新读时，以下入口是附件起草的普通独立合同已有的个人通道配方。必须先有可靠定位、当前 owner 或当前任务证据，并核实当前环境对具体请求的适配与对象权限。只读取用户明确要办理的这一份，不在列表、筛选或候选匹配中批量读取。原页面详情可能修正历史交易方数据；本次授权不涵盖这种页面访问行为时，继续使用安全已核快照或说明受阻，不把这个 GET 当纯读。首次申请无当前任务时省略任务参数。

```sh
contract-cli api call --channel web --profile '<已核 profile>' --as user --raw GET /open-web/web/clm/contract/info --query 'contractId=<已核合同ID>' --query 'tianyancha=false' --query 'generateContractName=false'
```

`tianyancha=false` 和 `generateContractName=false` 只关闭对应的查询和命名行为，不能关闭历史修正。响应只采用 `code=200`、`success=true` 且有 `data` 的对象，核对 `data.contractId`、`tenantId`、`ownerEmployeeId`（或已核权限字段）、`businessTypeCode`、`contractStatusCode`、`contractText` 及实际办理阶段。保留 `data.formId` 用于同对象流程绑定，`headerFormId` 用于表单配置，按实际结构分开。详情里仅保存本任务相关字段，不回显附件临时凭证或编辑器信息。接口成功仍须根据下表核对实际字段、权限、规则和候选是否完整。

`sourceTypeCode=0` 在原系统表示默认文件上传，`4` 表示开放平台创建。开放平台创建也可能上传了真实 DOCX；不能仅凭 `4` 判定可送审。核实本合同实际 `contractText`、文件 ID 或已获授权的上传产物、模板绑定与当前原页面前置。模板导出为附件不属于本期，不能用扩展名推断正文来源或用来源码替代当前对象权限。

结合已核的运行态结果映射如下。若实际入口的数据结构不同，只有具备等价含义且已核对字段映射时才继续。

| 原页面信息 | 用法 |
| --- | --- |
| `moduleInfos`、`attributeInfos`、`groupInfos` | 保留实际模块与组顺序及字段关联，结合 `deleted`、`templateVisible`、字段/组的 `checked` 和当前业务阶段判断。 |
| `processAttributePermission.attributePermissions`、字段 `optionConfigs`、`editDisabled` | 结合当前节点、页面可见与可编辑规则确定访问权。没有查看权的字段值不输出；组件层另有规则时须一并采用。 |
| 标准字段值、`schemaValueMap`、`presetSchemaValueMap`、`tableValueMap` | 分别取得字段原值和明细。当前字段键、标准字段别名及类型沿用页面的真实含义；不通过显示名反推键、值类型或提交结构。 |
| 当前候选值域、联动条件、默认值与系统派生结果 | 用当前合同适用的规则判断当前值是否合法。若依赖外部结果、数据未加载、冲突或无法核对，保留待核实。 |

## 编辑工作表

为每个当前可见且适用的字段保留稳定键、分组与顺序、字段类型、系统原值、原页面预填值、提取建议、拟提交值、各值来源、权限/禁用、必填、空值及真实候选。使用实际字段键加组/明细行身份识别同名字段；展示写业务名称。标准字段、合同自定义字段、组合值和独立明细使用各自键和值类型，不合并同名字段。提交始终保留真实主数据 ID 与显示值的对应关系。

保留字段实际的必填性、判空、权限和合法性，用于[对话内表单展示](#对话内表单展示)。没有查看权的字段不展示，获权只读字段显示只读。区分字段缺失、空字符串、空多选、合法的 `0`、`false`、含义为「无」的有效枚举。组合值按组成项与页面规则判空，金额为 0 时仍单独核对币种、金额适用性及区间校验。

- 有限枚举分别列出当前选项和其余有效选项。多选保留已选集合；旧值下架但仍允许展示时，标注当前已存但不可再次选择，是否必须更换依页面行为决定。部门、人员、选项和金额组子字段的原生查询及保存映射见[独立保存](field-save.md#字段取值)。
- 人员、部门、交易主体、关联单据等动态候选按当前合同、字段、权限及联动条件查询。展示已确认的候选范围和分页，允许继续按词选。不能确认全部时明确「本页／本次搜索结果」；候选读取失败时不显示「无选项」。同名用获权可辨信息让用户选定；不自动创建主数据或继承另一份合同的选择。
- 用户可一次编辑多项。按真实字段与选择校对输入；歧义仅就冲突项提问，其他明确输入保留。保留系统实值和对话拟提交值两个版本，仅对用户确认的值和真实规则派生值做对话内变更。明确清空与未修改分别记录。

## 对话内表单展示

用户提出提交审批时，按以下顺序呈现同一个表单。首屏和最终送审确认均展示全表，包含已有值、空的选填项、只读项及自定义字段。收到修改后先展示更新后的进度与本轮变化，用户可随时查看全表。

1. **表单概览。** 展示合同名、编号及当前页面动作。字段清单完整且适用范围已确定时，显示「共 X 项 · 有值 Y 项 · 未填 Z 项」，有待核实的值时另显示其数量，三者合计为 X。必填规则完整时，显示「必填 R 项 · 已就绪 P 项 · 待处理 Q 项」。Q 是 R 与 P 之差，按待填写、待确认、待修正、待核实的实际原因提示。值合法且无需用户再处理的必填项才计入 P。已提取、待采纳的建议本身不计入有值或已就绪。
2. **现在要处理的项。** 集中列出可立即填写的必填项、需要用户采纳的提取结果和实际冲突。可复制回复「采用以上提取结果」或以「字段名=值」一次补多项。对需要输入的字段直接给格式或实际可选项。只读缺项说明需由哪个系统步骤或有权限角色处理。按[提取结果确认](#提取结果确认)引导用户，已确认仍有效的字段直接带入后续轮次。
3. **全部字段。** 复用原页面分组名和顺序，每组显示当前可见字段数。表格用「字段｜要求｜当前值｜状态 / 可选项」。要求统一使用「必填」「选填」或「待核实」。当前值优先采用同一工作表已确认的本轮值，其余显示已核系统值。确认无值显示「未填写」，读取不足显示「待核实」。状态写「已填写」「待填写」「待确认」「待修正」或「待核实」，适当标记「只读」或「已采用」。空的选填项标「选填未填」，可留空。选项类字段在最后一列给出其余实际可选项。提取建议在同一行的状态中注明建议值，不单独凑成一行。可填写的字段从全表能直接定位。

总数按本用户当前可见且适用的页面字段计。包含可见只读字段。跳过标题、按钮、帮助提示和条件隐藏项。以原页面真实字段为单位，同一字段的建议、显示名和内部键只计一次。组合字段按页面实际输入项计数，只有独立字段才分开计。原页面以单个明细表或附件控件呈现时，按一个表单字段计，另列明细的行数及需补齐的单元格或文件，不将它们混入表单字段总数。

只能取得部分字段时，概览显示「已核对 X 个字段 · 完整字段总数和必填进度待核实」，各组只标已核对数量。只对实际可证的行标记已填、空值或选项。若清单完整且仅有部分值未知，仍可给字段总数，把未知值单列，必填统计仍以实际规则为准。任何未知项不得冒充待填写项。保留能确认的提取建议并引导用户处理。完整送审确认使用取得的实际全表。

## 提取结果确认

- 按本合同的实际字段在「现在要处理的项」中直接展示可靠的自动提取结果，可带单位和简短原文依据。例如「合同总额 420,000 元人民币。请确认是否采用，也可以直接给出修正值」。有多项时列出本次待确认的值，支持一次「全部采用」或点名修改。确认问题直接询问是否采用提取值。
- 同一字段有已知且不同的当前表单值时，显示两个具体值，请用户选择保留现值或采用提取值。当前值和提取值相同的合并展示。无法读到系统原值时，仍可就已核实的提取结果取得用户选择，在实际写入前按原协议核实原值、字段权限和适用规则。
- 收到明确采纳或更正后，把通过字段映射的值**立即填入本轮送审表单**，显示「已采用」和新值，沿用后续联动规则并继续引导需要补充的项。已确认且有效的值随表单流转。主体匹配、单位或字段语义有歧义时保留用户确认的内容，仅追问无法解析的部分。单独的保存请求按[独立保存](field-save.md)执行，发起审批遵循[最终确认](submit.md)。

## 联动复算与就绪判断

在初始化及每次修改后，用当前行/表单的拟提交值与实际规则重新计算。多个输入同时给出时，先识别决定其他项取值的输入，再验证其他输入在新条件下是否有效。应用页面实际的 `VISIBLE`、`SHOW`、`REQUIRED`、`SHOW_OPTION` 和字段值域、节点权限、计算及服务端结果；不能把 `needed` 单字段当最终必填。常见触发包括收支/计价到对应金额及币种、期限类型到起止日期、部门或交易主体到受限候选、自定义条件到显隐和必填。举例只用于帮助理解，最终依据当前表单配置。

按受影响范围继续复算到稳定。保留仍合法的值；当选项失效、字段新增必填、页面要求清除或可采用派生值时，展示变化和原因。隐藏值的清除、暂存、恢复或保留按字段原规则执行，不能统一删除或保留。若恢复的旧值不再有效，请用户重选。系统计算和只读值展示结果，不让用户填入猜测结果。校验加载失败、不稳定或条件未知时，保留已有确定值，列明未决项，停止宣告就绪。

每轮按稳定后的实际规则重算[表单概览](#对话内表单展示)，展示新增、隐藏或改为必填的字段、无效值及仍需用户操作的项。对需补项给真实选项、必要输入格式和业务内容建议。修改阶段先保留拟提交值。拟提交值覆盖全部当前适用必填项、相关候选已核实、字段初步合法且联动稳定后，提示必要字段已填写，并按已核动作邀请用户进入完整确认。准备校验尚未完成时展示具体原因及下一步。随后进入[普通送审确认](submit.md)或[二合一确认](cooperation-submit.md)，按原页面处理后续校验。

交给提交步骤的记录包括同一对象和本轮身份、适用字段与值、格式化展示、基线/待改值和明确清空、已核有效候选、实际联动结果、正文文件与版本、当前表单版本（无版本字段则保留可核对的表单规则、权限与原值快照）。最终复核若发现对象、版本、原规则或拟提交信息变化，按变化重新求值并撤销旧确认。
