# 场景覆盖与特殊页面入口

本页维护对象归并及特殊路由。普通独立草稿、模板判据和协商子状态的唯一规则在[系统页面入口](native-page-handoff.md)。来源不是权限；点击入口后，全部填写、正文同步、保存、校验和提交由用户在系统页面操作。

## 来源对应的真实对象

| 来源 | 保留的业务对象和边界 |
| --- | --- |
| 上传、复制、模板、可编辑/不可编辑模板、开放平台/CLI创建 | 已生成的实际合同；普通草稿按草稿选择器，当前协商完成按完成态分流；不因来源不同排除已有草稿 |
| 框架下的子合同 | 真正独立子合同按自身办理，保留框架关联；不当作合同组成员 |
| 上传或模板补充、终止协议 | type2/type3 申请自己的 ID，不用原合同 ID；定制补充 type16 同理 |
| 修改合同信息 | type12 变更单自己的 ID；直接修改原合同不是提交变更单 |
| 合同组 | type10 父组；成员常为type11，先核真实父组关系及当前父级办理依据，再归并父组入口 |
| 模板多合同/系统批量 | type17 父组；成员也可能是type0，不能凭type0判成独立合同；按真实关系核父级办理入口 |
| 协商合同 | 真实协商/当前轮 + 实际底层业务关联；不得将 cooperationId 当合同ID，也不能把成员协商当父组协商 |
| 拒绝/撤回 | total4/2 与当前真实可重提待办；不是首次送审 |
| 作废申请 | type15专用单据/弹窗，见下节；不能套普通 edit |
| 履约确认/到期提醒 | type14单据或原合同明确提醒动作；不是普通合同首次提交 |
| OA、Bot、拍照、移动存储、云文档、范本 | 已生成真实合同后按实际对象族办理；不为链接调用文件内容解析或来源专用写接口 |
| 多份独立文件 | 保留逐份真实合同，不创建合同组；同对象去重，同名不同对象保留 |
| 电子签位置及签约信息 | 属于该对象页面前置；链接不代表已启动签署，页面可能先引导签章位置 |
| AI起草文件、独立审查文件 | 文件不是合同；复用用户已授权的上游准备结果，不用文件ID拼合同页面 |
| 续签 type1、重新出具 type19 | 当前没有本包可执行的独立提交路径；仅复用本轮已有可信具体页面，或给获权对象查看入口；不从枚举猜路径、不为此新增系统功能 |
| 历史台账导入、模板定义、预审、评论 | 不是可直接首次送审的新申请；有新申请则定位新ID |
| 已作废、流程中止、提交中 | 不自动恢复、重建或重试；显示实际阶段及已核查看入口 |

没有已创建申请时，只在用户明确要发起对应新业务时给原合同的真实创建入口。不得为了填满“可提交列表”自动新建补充、终止、变更、作废或履约单据。

## 组草稿与查看

以新鲜的本人草稿组列表（searchTabCode=3）或已有获权父组上下文核实父组 ID、类型、状态及当前负责人范围，资格见[权限边界](permissions.md)。本人列表的父对象 contractId 是组ID，必须保持 assembly 域；模板组使用自身真实 templateId。当前组关系未知、仅有成员读权限或未取得父组依据时，不自动拼组提交链接，也不能将缺少 assemblyId 解释成没有父组。合同版本 groupId 不能代替 assemblyId。

| 当前对象 | 路径和参数 |
| --- | --- |
| 本人普通合同组草稿 type10 | /apply/assemblage/edit，query contractAssemblyId=真实组ID、from=management-draft |
| 本人模板多合同草稿 type17 | /apply/assemblage/template/base-info，query contractAssemblyId=真实组ID、templateId=实际组模板ID、from=management-draft |
| 普通组查看 | /management/all/detailAssembly/真实组ID |
| 模板多合同组查看 | /management/all/detailbatch/真实组ID |

合同组操作文字可为“提交审批（整组）”，保留原输入成员对应关系，不逐成员启动。模板组从系统第一页恢复分别/统一填写，不猜跳到最后一步的路径，不用空父组明细推断成员无需填写。状态、类型或模板信息不足时给有依据的查看页并说明；不调用旧组准备/导出接口补齐链接。

### 父组与成员的协商边界

普通父组10、模板多合同父组17的当前原生常规流程不提供整组发起/完成协商入口：组草稿走保存/提交；审批任务不提供父组协商按钮；拒绝、撤回后修改组信息重提。不能因有 consult/coop_after_reject 配置就给父组“去协商”或“协商完成后提交”链接。组提交能力仍按上表和下节保留。

这不等于所有组成员都没有协商。遇到真实成员协商时，保留成员、协商及已获父组关联，按当前已知对象给准确的协商承载页；成员完成不证明父组完成或整组可提交。尚不能安全核实父组关系时标“打开协商页面”，说明父级办理关系未确认；没有可核实入口则说明暂无法定位，不拼父组链接、不拆组送审、不把该限制变成系统改造任务。

一次上传多份独立合同仍逐份出链接；只有实际创建结果或获权查询明确返回父组关系，才按组归并。文件数量、同名、同批上传和模板来源都不能替代父组关系。

## 重提与专用入口

按[查询协议](query-protocol.md)通过本人 TODO 列表取得候选，或复用本轮真实任务候选，再用 task/info 核对对象、当前待办及实际处理人。CURRENT_TODO只证明任务承载入口；直接重提还须本轮已有可信的修改/重提动作快照及实际页面依据，见[权限边界](permissions.md)。不调用 permission/business/list 补能力，不能取第一条历史任务、用抄送代待办或用字段 WRITE 代重提权限。缺完整动作依据时给“打开当前任务”；连当前任务也无法确认时只给已有获权对象页，不猜重提参数。

| 当前场景 | 页面入口与额外说明 |
| --- | --- |
| 已鉴权的当前本人待办，但未核完整重提条件 | /task-center，query taskInstanceId=该对象真实当前待办ID；标“打开当前任务”，由用户按页内实际动作继续。多个当前任务保留节点区分，不自动选最新一条 |
| 独立合同审批撤回/拒绝，当前任务明确可修改/重提 | /apply/edit，query contractId=当前申请ID、from=task、processTaskInstanceId=当前待办ID；仅当前可信入口明确带 afterCoop=true 时保留。普通/模板使用真实当前任务入口，不为查 afterCoop 读取完整详情；存在当前协商前置或从协商完成继续办理时，优先按[系统页面入口](native-page-handoff.md)处理 |
| 普通组撤回/拒绝 | /apply/assemblage/edit，query contractAssemblyId=真实组ID、from=task、processTaskInstanceId=当前待办ID |
| 模板多合同组撤回/拒绝 | /apply/assemblage/template/base-info，query contractAssemblyId=真实组ID、templateId=组模板ID、businessTypeCode=实际组类型、from=task、processTaskInstanceId=当前待办ID |
| 作废申请修改/重提 | /task-center，query taskInstanceId=该单据真实待办ID；标“处理作废申请”，说明进入任务后点“修改作废申请”打开弹窗 |
| 明确申请作废意图 | 已核原合同/组详情页，标“到页面申请作废”；用户在页内点“作废”，不制造直达弹窗参数 |
| 明确发送到期提醒意图 | 已核原合同详情页，标“到页面发送到期提醒”；按钮受系统当前 completeOperate 与规则约束，发送提醒不等于已履约 |
| 已有履约确认 type14 及真实任务 | /task-center，query taskInstanceId=该单据真实当前任务ID；标“查看/处理履约确认任务”，不凭类型假定可重提 |

编辑页参数名为 processTaskInstanceId，任务中心参数名为 taskInstanceId，值均须来自当前对象获权任务。当前轮 todoTaskId 可按[查询协议](query-protocol.md)验证后映射，不能仅凭名称相似或字段存在直接采用。任务中心 noticeId 仅真实存在且属于本次抄送查看入口时保留，不能赋予重提权。无真实当前任务时不提供虚构任务链接，说明可从已核原合同页面继续查看。

## 真实变更上下文

从原合同“继续已有变更草稿”进入时，仅沿用本次已核实际分支：

- 已有信息变更单：/apply/edit + 自身 contractId + from=change。
- 已有补充/终止变更草稿：实际原入口有 templateId 则对应 /apply/template，否则 /apply/edit + from=changeRecord。
- 实际原入口将 total30/31 导向协商：/cooperation/detail + 当前 cooperationId + from=change + hasDraft=true。

这些参数不能由“合同是变更类型”泛化给所有草稿。来自本人草稿列表时保留实际列表入口；来自任务时以当前任务入口优先。原动作可能创建新单据，因此本包不通过点击创建或调用创建接口取得新ID。

所有路由先绑定已核 HTTPS origin，再用 URL/URLSearchParams 生成。仅承载页的入口要明说后续需点哪个动作，不能把“有承载页”描述为能直达提交弹窗。
