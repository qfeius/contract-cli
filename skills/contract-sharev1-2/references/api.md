# 合同分享接口与通道

以下是普通合同页面链路的请求及返回协议；路径映射已确定，不代表目标环境已启用。只调用具备当前用户权限、已满足准入条件的入口。已有专用业务工具满足同一协议时优先复用。

## 通道与结果封装

CLM family 原页面路径 `/clm/api` 对应公共前缀 `/open-web/web/clm`。本文件使用公共相对路径，不在 path 拼接域名、query 或凭据。当前环境、租户与组织用户由宿主通道提供，不把它们加进业务请求充当身份。

CLI 能力以宿主实际安装为准，本包不自带执行器。使用 CLI 时先读取 `contract-cli api call --help`，确认支持 `--channel web`、method/path、query、请求原文、profile 与原始响应。已知形式为：

```sh
contract-cli api call --channel web GET /open-web/web/clm/systemConfig/share/config --raw
```

需要已确认的 profile 时加 `--profile`；支持时用 `--as user` 明确用户身份。全流程保持同一 profile；不得从文档示例推导实际环境。GET 参数用可重复的 `--query 'key=value'` 传递。写入 body 使用 `--input-file` 或 `--data` 二选一，不以二进制浮点序列化长整型 ID。`--raw` 原样取得响应，后续仍须无损解析。

MCP 核对宿主实际工具 schema；已知通用入口名为 `call-open-web-api`，仅在确实可用时采用，不把这个名称当作已安装。按其 schema 传 method、path、query、body 或 raw_body；body 与 raw_body 互斥，不能照搬 CLI 参数。

原始 CLM JSON 通常以数字 `code=200` 表示业务成功，业务结果在 `data` 中。网页请求封装额外产生的 `success=true` 不是原始响应固有字段。宿主若进一步包装响应，按已核实的层级提取；解析不明时停止，不递归猜一个 `data` 就继续。HTTP 200、工具未报错、预检查允许，均不单独证明写入成功。下述 `data.*` 指解开已知包装后的 CLM 业务字段。

所有合同、员工、记录及授权 ID 均作为不透明十进制字符串保留。DTO 的 Long 字段在原文中按真实数字 token 无损写出，不能先转换成 JavaScript Number；字符串字段按字符串传送。若通道不支持保真则停止对应请求。不能以合同编号、合同组 ID、账户 ID、飞书 openId 替换合同或员工 ID。

## 接口准入与停止条件

| 业务范围 | 条件与停止点 |
|---|---|
| 读取配置、已授权详情与分享记录 | 源码显示各自权限实现；目标环境身份、路由及适用版本仍需核实。无依据时报告待接入，不试探数据范围 |
| 分享权限预检查 | 可作单对象预检查，但不校验真实状态，也不证明请求最终授权范围；不能用于绕过后续判断 |
| 员工解析 | 依赖组织员工的既有可见范围规则；取数范围证据不足时先核实，不先读全租户再过滤 |
| 多合同批量创建 | 每份请求合同及实际展开对象均须逐一核实权限、状态、接收人与期限；全部通过后可提交正常多资源请求。任一对象被拒或未知时停止原批次，不能依赖后端自动剔除无权对象；用户未接受新计划时不缩减或拆分 |
| 期限控制开启时创建（单份或批量） | 不因开关开启而整体拦截。实际授权范围、接收人、权限及状态均已核实，且未命中本表其他受阻分支时，显式发送 `hasExpiration=true` 和合法 `expirationTime`，按下文创建与回查协议执行。字段不一致、期限已过或超上限、配置异常或时区不明时停止；不构造错误参数试探服务端 |
| 要求部门限制的分享 | 创建时部门校验有缺口；缺少有效服务端限制依据前停止，不以选人组件限制代替 |
| 按记录取消，以及依赖取消的改期 | 必须使用当前目标合同记录查询新取得、归属和业务类型核对一致的记录，配合该合同的当前访问权限及用户授权后执行；错配、来源不明或归属无法核实时停止。改期另须满足新建及取消后仍有权限的条件 |
| 会展开关联对象的创建 | 必须在写前取得可靠的完整展开清单及逐对象权限；现有详情不足时停止，不猜关联对象，也不以写入探测范围 |

以上限制针对具体动作和范围，不整体禁用 CLM 服务。期限正常请求遵守字段一致性和回查协议，无需先取得系统整体修复证明；这不修复服务端对错误请求的校验。批量与取消使用本表的对象级准入条件，不把后端缺少通用防御等同于所有正常请求不可执行；后端缺陷仍需独立修复。部门限制分支的修复门槛保留，登录、用户确认或一次成功不能替代该分支的修复依据。没有当前调用器不等于业务 API 不存在，应报告缺少执行能力。

## 准入说明与验证边界

本包提供业务流程与源码接口协议。复用验证证据时，应核对适用环境、租户、用户、版本和对象分支；文件校验或某环境读取验证通过，不等于写入、其他环境或其他对象分支已经验证。

企业开启期限控制本身不是禁止分享的理由。单份合同的实际授权范围、接收人、权限与状态明确时，正常创建请求按期限协议发送一致的有效期参数；不将服务端缺少错误参数防御扩大为禁止所有正确参数请求。批量逐对象检查、取消记录归属核对、部门限制及关联范围检查分别适用。

正常批量与取消不以缺少系统整体修复证明为唯一停止理由；具体授权条件未满足仍须停止。客户端核对仅约束本 Skill 发出的请求，不证明后端缺陷已经修复，也不等于线上写入已经验证。实际准入条件统一维护在上方表格，本节解释其适用边界。

## 合同定位和详情

名称／编号搜索复用宿主已核实的当前用户可见合同查询协议，本包不虚构搜索命令或字段。不具备查询能力时，可请用户提供合同详情链接。

GET `/open-web/web/clm/contract/info`：query `contractId` 为详情链接或可靠查询得到的合同候选 ID，字符串；`tianyancha=false`，不触发与本任务无关的企业外查；`generateContractName=false`，不生成合同名称。不附带无来源的 `noticeId`、`taskInstanceId`。

已知详情结果为 `data.contractId`、`data.businessTypeCode`、`data.contractName`、`data.contractNumber`、`data.contractStatusCode`、`data.contractStatusName` 及 `data.createEmployee.employeeId` 等业务字段。状态判断用 `contractStatusCode`，不从名称或标题猜枚举。只保留任务所需字段，不传播合同正文。成功返回的合同 ID 应与候选一致；权限拒绝时不得尝试其他身份。

`data.businessTypeCode` 用于分享请求与记录查询，不固定为合同申请的 0。已知 2 为补充协议、3 为合同终止、9 为历史导入、10／11 为合同组相关类型、13 为原始信息、16 为定制补充协议；不同类型的关联影响不可套用普通申请。其他类型须有适用协议，不能通过修改类型码绕过。

详情并不保证提供服务端关联展开所需的全部字段；不得依赖一个未核实的 `nextId` 或前端卡片清单证明完整范围。

## 人员解析

页面直接搜索使用 GET `/open-web/web/clm/employee/findEmployeesByKeywords`。此入口已标记废弃但仍被分享弹窗使用，不自动换成参数相似的新入口。

优先按用户提供的姓名查询；组织数据包含且查询能力支持邮箱匹配时可尝试邮箱。邮箱未命中时，用本轮用户已提供或已可靠确认的姓名重新查询；没有可靠姓名则向用户确认。不得从邮箱前缀猜姓名、自动选择相似账号，或把空结果当作此员工不存在。候选的 `email` 为 null 时，用可靠姓名及部门等信息消歧，不虚构邮箱关联。

| query | 类型及来源 |
|---|---|
| `keywords` | 必填非空字符串；按本节规则选择用户提供的姓名，或具备匹配依据的邮箱关键词；不保证组织数据具备邮箱 |
| `filterCurrentEmployee` | 布尔，页面快捷搜索默认发送 `true`。用户明确指定当前员工且当前查询协议适用时可发送 `false`，仅取消候选过滤，不改变身份或业务权限 |
| `filterEmployeeIds` | 逗号分隔员工 ID 字符串；页面默认过滤当前员工和详情创建员工。沿用过滤时来源必须可靠，不拼 `undefined`；用户明确指定被过滤人员时可按此接口已核实的参数使用空字符串 `""`，仍限定同一租户、有效员工和用户指定对象 |
| `includeInvalid` | 本流程传 `false`，不扩展到无效员工 |
| `needQueryRoleInfo` | 本流程传 `false`，不读取无关角色信息 |
| `filterVisibleEmployee` | 页面未显式发送；只有当前组织协议要求且已核实语义时才指定，不擅自放宽范围 |

响应 `data` 是员工数组，使用 `employeeId` 对应创建参数；用 `name`／`displayName`、必要的 `departments`／`email` 消歧，用 `tenantId` 对照当前租户。没有 tenantId 时不能凭空补成当前租户，须由已核实的组织查询协议证明租户边界。该响应不提供本流程可续页协议，不能承诺员工全量枚举。

页面快捷搜索会排除当前员工和详情创建员工，但这是候选过滤，不是已经核实的服务端禁止分享规则。不能因为默认列表没返回就拒绝用户明确指定的这类人员；在已获准的组织查询范围内按上述参数重新查找并消歧，实际分享仍由创建接口校验。不得清除组织可见范围、无效员工或租户边界限制。对来源可靠的接收人集合只去除同一次请求重复的员工 ID，不去除历史分享记录。

## 配置与分享预检查

GET `/open-web/web/clm/systemConfig/share/config`，无 query/body。读取 `data.enable`、`durationSwitch`、`reshareSwitch`、`shareDurationType`、`reshareScopeType`、`autoCreateChatGroup`。布尔 `false` 和数值 0 必须保留；响应缺失不能自动填默认配置。期限判定由 `enable && durationSwitch` 决定，业务含义见业务规则。

GET `/open-web/web/clm/contract/share/shareable`：query `businessId` 为已验证详情的 `contractId`，字符串；`businessTypeCode` 为详情中的整数类型。读取 `data.code`：0 不可分享，1 员工所属部门，2 所有部门；`shareScopeType`／`name` 可辅助解释，不代替 code。未知 code 停止创建；顶层 `code=200` 与 `data.code=0` 不矛盾，表示查询成功但不允许分享。

## 分享记录

GET `/open-web/web/clm/contract/share/record`：query `contractId` 为已验证详情的合同 ID 字符串，`businessTypeCode` 为该详情业务类型整数。需要合同管理页面权限、数据权限及合同访问权限。

`data` 是该合同记录数组，无本流程续页参数；每项读取：

| 字段 | 用途 |
|---|---|
| `id` | 分享记录 ID 字符串，取消、前后比对使用 |
| `businessId` | 该记录资源 ID，必须与被查询合同对应 |
| `businessType` | 记录业务类型；原始枚举表示须按实际 schema 解释，不能直接当数字类型码 |
| `fromEmployeeId`／`toEmployeeId` | 分享人／接收人员工 ID 字符串，关联创建结果及身份 |
| `fromEmployeeName`／`toEmployeeName` | 展示姓名，不能反向作为身份标识 |
| `hasExpiration` | 为 false 时 endTime 不代表真实到期时间 |
| `startTime`／`endTime` | 此接口按 `yyyy-MM-dd` 展示，不能证明精确秒级时刻或唯一创建时间 |
| `enable` | 记录启用状态；false 不能区分到期与人工取消，true 也不代替时间有效性判断 |

权限拒绝、解析错误、字段缺失与空数组分别处理。空数组仅代表本次成功查询未返回记录；完整性只覆盖此接口当前合同范围，不代表租户全部合同记录。

## 记录业务类型映射

本地模型 ShareRecordVO.businessType 为 BusinessType 枚举，合同详情使用整数 businessTypeCode。普通枚举字符串可按下表转换，不能按中文显示名匹配（不同类型可能同名）：

| 枚举名 | 详情类型码 |
|---|---|
| CONTRACT_APPLICATION | 0 |
| CONTRACT_RENEW | 1 |
| CONTRACT_CHANGE | 2 |
| CONTRACT_TERMINATE | 3 |
| CONTRACT_IMPORT | 9 |
| CONTRACT_ASSEMBLY | 10 |
| CONTRACT_ASSEMBLY_CONTRACT | 11 |
| CONTRACT_ORIGINAL | 13 |
| CONTRACT_CHANGE_CUSTOMISED_SUPER_MONKEY | 16 |

此表仅用于对象类型对照，不新增这些类型的分享权限或消除关联展开要求。若目标通道返回数字、对象或其他表示，先核实其实际序列化协议再转换；不要递归搜索任意 code 或猜枚举。未覆盖类型停止受影响的取消步骤，不影响其他已核实对象。

## 创建分享与回查

POST `/open-web/web/clm/contract/share`，JSON body：

| 字段 | 类型、来源与发送策略 |
|---|---|
| `businessResourceDTOList` | 对象数组；资源来自已验证合同详情。多资源请求受批量准入限制；单资源也要先核实关联展开 |
| `businessResourceDTOList[].businessId` | Long 数字原文，来自详情 `contractId`；无损保真 |
| `businessResourceDTOList[].businessTypeCode` | 整数，来自同一详情 `businessTypeCode`，合法的 0 不得省略 |
| `businessResourceDTOList[].tenantId`／`parentId` | 普通页面未发送，本流程省略；不把 groupId 填成 businessId |
| `shareToEmployeeIds` | 字符串数组，来自已确认员工的 `employeeId`，非空且不超过 50 人 |
| `hasExpiration` | 布尔，期限控制开启时必须显式 true，并同时发送经过校验的 expirationTime；正常无到期流程显式 false 并省略 expirationTime，不依赖 null 默认 |
| `expirationTime` | 有期限时为业务时区的 `yyyy-MM-dd 23:59:59`；无到期时省略，不发送歧义空字符串。仍须以当前部署 DTO 日期解析协议核实实际时区 |
| `reason` | 可选字符串，仅在用户提供且愿意写入时发送；没有时省略，不自动加入内部记录或诊断信息 |

提交前核对实际 JSON：期限控制开启时 hasExpiration 必须为 true，expirationTime 必须存在且未过期、未超上限；缺失配置或未知期限枚举不能按后端的默认放行分支继续。不要把 false/null 与有效日期组合提交。

正常页面单资源分享可能拉群或发通知，写前纳入确认。不要调用 `shareAll`、开放平台批量分享或管理员接口来绕过普通页面权限。

响应解包后读取 `data.isPartlyShareFailed`、`data.shareRecordVOList`，可有 `data.authorizations`。只有顶层业务成功还不够：逐个核对返回记录的 `id`、`businessId`、`toEmployeeId`、`fromEmployeeId`、`hasExpiration` 及期限；返回集合须与预期资源×接收人一致，额外记录、缺少记录或部分失败都要单独报告。记录缺失或为 null 不当成空成功。

写前取记录基线，写后用返回的每个记录 ID 在同一合同的记录接口回查，确认新 ID 不在基线且与创建响应及操作对象一致。若关联资源缺少回查能力，不能把整个分享标为已验证。日期字段的精度只允许确认日期，不据此声称已在线验证 23:59:59。期限控制开启时，创建响应与回查记录均须 hasExpiration=true，截止日期与已确认日期一致；如返回了关联实际授权的 authorizations，按当前协议核对其期限，不能只检查显示记录就声称实际授权已到期受控。实际授权期限不可读取时明确报告“分享记录期限已回查，实际授权期限未独立验证”。出现无到期、日期不符、额外对象或其他不一致时报告异常并停止后续写入，不宣称成功、不重复创建，也不自动取消补救；取消须作为独立动作，重新核对记录归属、权限并取得覆盖该记录的授权。

超时或解析失败没有返回记录 ID时，可以读基线后的记录变化辅助核实，但同人同日期或单个新增 ID都不足以排除并发操作。需要获准的可靠请求追踪证据建立因果关联；否则报告“提交结果未知”，停止重发。即使返回部分失败，也先按实际新增记录核对已完成部分。

## 取消与回查

PUT `/open-web/web/clm/contract/share/cancel`。通过目标合同当前记录查询取得指定记录，并满足本表归属与权限条件后发送 JSON。该核对约束本 Skill 的请求，不表示服务端对任意请求已补齐归属校验：

| 字段 | 来源及约束 |
|---|---|
| `contractId` | Long 数字原文，来自目标记录 `businessId`，必须等于已验证的目标合同 ID |
| `shareIdList` | 字符串数组，恰好一项，来自该合同记录查询返回的 `id` |

写前必须重新读取目标合同及其记录并保留快照。记录 businessId 必须等于该合同详情 contractId，businessType 按已核实的枚举映射与详情业务类型核对；映射未知时停止，不能直接比较不同表示。记录必须来自同一环境、租户、用户上下文的本次查询，且对应用户指定的接收人和具体记录。已停用则只报告当前状态，不发写请求。不可按姓名合并取消，也不以调用者是原分享人作为必要条件。`data` 为实际取消的 ShareRecord 列表，只有顶层成功但没有目标记录时不能认定本次已执行取消。返回记录的资源与接收人也必须匹配写前快照；不匹配或返回额外记录时报告异常并停止后续写入。

返回包含目标记录后，再用记录查询确认同一 ID 已 `enable=false`。若没有对应执行回执但回查发现已停用，只能确认“当前已停用”，不能声称是本次请求唯一造成，也不能因此自动开始改期的新建步骤。已停用记录无需重发取消；相应结果应如实说明。接口明确返回目标取消记录但回查失败时，分开报告“接口已确认取消”和“后续状态未回查确认”；若因取消自己的唯一授权导致回查被拒绝，也不重发、不换身份。仅有顶层成功而无对应记录时保留执行结果未知。任何回查未确认均停止依赖它的后续写入。

取消只处理这条授权；不要查询其他人的私人会话验证访问，也不以本调用者能看合同证明接收人已失去权限。
