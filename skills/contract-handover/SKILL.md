# 合同交接

先读取 [通道与授权](references/transport.md)，确认当前环境与实际调用能力。按需读取下面的接口参考，不一次加载全部资料。

## 当前可处理的范围

- 只读：定位指定合同，查询当前归属人、申请人及接口返回的交接历史；不要求接收人或写入确认。
- 指定合同交接：将用户明确选择的一份或多份合同交给一个明确接收人；冻结清单后提交，逐份核对指定入口。
- 合同组：先按 [合同组参考](references/assemblies.md) 判断是否能完整读取并满足交接条件，不能套用普通合同规则。
- 不执行动态“全部搜索结果”交接、未知关联范围下的自动多批交接或跨租户交接；用户选择搜索结果中的明确对象后，仍须逐项进行交接预检。

搜索、预检、写入及回查必须处于同一环境、租户和用户授权上下文。实际通道不支持目标环境时，说明限制并停止，不通过切环境或改地址继续。没有可靠 ID 映射、读取或回查能力时不写入。

## 1. 明确合同和接收人

用户可提供合同编号、名称、可信合同链接或内部 ID，以及一名接收人。链接只解析已确认格式的标识，不直接访问任意地址执行操作。不让用户手抄内部 ID。

按 [合同定位与 ID 衔接](references/contracts.md) 优先复用本轮已选候选；缺少候选时读取已有 [合同搜索 Skill](../contract-cli-contract-search/SKILL.md)，在同一环境和 user 授权下查找。一般搜索条件和分页仍由搜索 Skill 处理；缺少父组 ID 时，仅按 [编号自动定位父组](references/assembly-lookup.md) 补充分组关系。搜索返回 ID 先按衔接规则确认其语义，再选择对应详情入口；重名或多候选时让用户选择，不默认第一条。

已取得可信父合同组 ID 时，直接按 [合同组参考](references/assemblies.md#父组定位与读取入口) 读取父组及完整成员；组成员的 `contract/info` 成功不是这条流程的前置条件。仅有编号或搜索成员时，Skill 自动补查父组并核对完整成员，不让用户手动提供父组 ID；不能把搜索 `group_id` 当作父组 ID。

需要交接时读取 [身份、权限与接收人](references/identity.md)，核对当前用户、功能权限和唯一接收人。只查历史不需要搜索接收人。

## 2. 说明会发生什么

读取当前归属人和申请人，不能以创建人代替当前归属人。普通归属人交接的预期如下：

| 交接前 | 预期变化 |
|---|---|
| 归属人与申请人相同 | 两者一起改为接收人 |
| 归属人与申请人不同 | 只改归属人，申请人保留 |

这是普通处理路径的结果规则，不是权限凭证。第三方、仅申请人操作者及组场景由各自权限与角色决定；未验证的分支不能按普通规则放行。服务端最终校验当前权限、状态和角色。

普通指定合同还须核对实际类型、状态、groupId 和 assemblyId。真实组成员转入合同组流程；关系不明时停止。明确已取消或依赖未核实配置的状态不能仅凭“有权限”执行。

后端可能联动同 groupId 的关联记录，并按既有规则处理草稿。指定普通合同的结果可以限定为所选入口，但必须把未知关联影响说明给用户，不能声称指定合同是唯一受影响对象。用户明确要求“其他合同或草稿都不变”而现有接口无法保证时停止。

## 3. 确认后执行一次

展示本次清单：合同编号／名称、接收人及部门、当前与预期归属人／申请人、已知关联影响、排除项和原因。未知影响不填成 0。普通合同同时说明：

> 接口可能联动同组关联记录，并按系统规则处理相关草稿；本次核验指定合同的交接结果。

用户确认具体清单与处理方式后，读取 [交接请求与结果核对](references/handover.md)。同一对象、接收人和影响已有明确授权时可以沿用；范围、接收人或新增影响变化时重新确认。

写前重读接收人和入口关键状态／角色；变化时暂停并更新清单。普通合同先提交一个批次，完成核对后再考虑剩余清单，每批最多 100 个去重入口；不根据搜索条件动态交接，也不自动追加新命中。合同组整体处理，不拆成成员写入。

先按 [资源类型与 ID 选择](references/resource-types.md) 核对业务码与入口，再按真实详情生成 resourceList，使用已核接收人 employeeId 和 tenantId。只调用同步交接一次；不添加管理员、操作人或只改某种角色的参数。

## 4. 回查并报告

先判断通道与业务结果，再回读本次指定合同。合同组使用父组 `info` 与 `childrenInfo` 完整分页回查，不额外要求逐份调用成员 `contract/info`。结合写前快照、本次授权／新增交接记录及实际角色变化逐份判断，不能把整体 success=true 或旧历史当成本次全部成功。

输出以合同编号／名称、状态、实际角色变化和已知原因组成的简明表格，汇总成功、无新增变化、失败、跳过、待核实及未执行数量。可用且已确认的合同链接可以附上，不补造链接。

- 原归属人与申请人不同的普通合同，要核对申请人确实未改变。
- 超时、断网、5xx、缺响应或回查矛盾：停止后续操作，只读核对；不重试、不换通道重放、不交回原人当回滚。
- 明确续办时重新核对剩余范围；原未决对象及与其有共同影响的对象不得重复提交。范围不变的明确续办授权不重复询问。
- 指定入口结果与关联资源、草稿、流程、授权及通知的核验情况分开报告；未知副作用不能宣称全部通过，也不自动抹掉已有证据的指定合同角色结果。

仅查询历史时直接返回当前角色及历史中的交接前人员、接收人、操作人和时间；缺字段照实说明，不触发交接，也不把历史称为本次操作。
