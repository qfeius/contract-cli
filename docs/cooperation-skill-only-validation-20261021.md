# 协商 Skill 编排补齐与验证（2026-10-21）

## 本次修改范围

只更新 `skills/contract-cooperation` 的文字规则与参数附录，以及 README、验证记录和 AI 变更记录。CLI Go 源码及 MCP 请求 DTO 的前后哈希一致；没有修改后端、CLI 参数或前端，也没有发布、推送或修改生产业务数据。

- 多发起人按已确认的开放 user_id 去重后逐人查询，保留共同条件，每个人独立读完分页，按 cooperation_id 合并。
- 同名但 ID 不同的协商分别保留；长 ID 不经浮点数转换。字段冲突保留首条并说明，缺 ID 单列，分页异常或失败不能声称完整结果。
- 确认人数展示使用接口已确认人数/总人数，区分 0、缺失、异常；与总体状态独立，不推断“全部节点已确认”或当前用户能否确认。
- 保留页面状态映射、已有顶部视图及状态/类型/日期/部门/角色参数规则。两组需要后端参数的确认筛选继续报告不支持；没有发送这些字段或调用页面通道。

## 验证方式

先进行独立基线试用，原 Skill 无法明确完成多发起人合并和人数异常值处理。更新后由另一独立代理只读新 Skill 和模拟响应，给出逐请求 JSON、分页轨迹及展示结果；未向其提供预期答案或基线报告。该部分为离线行为试用，不冒充生产执行。

生产部分复用已有 prod / contract / user Device 授权，通过现有 CLI 及 user MCP 查询。主验证包含 7 组场景、25 次搜索，另有 1 次分页预检查、3 次人员查询、2 次详情核对。原始响应、人员 ID、日志、模拟用例和独立试用报告仅保留于本机临时目录，不进入仓库。

## 生产 MCP 结果

基准为本次完整读取的“我的协商”4 条，每页 1 条。三名发起人均用真实开放 ID；姓名检索存在多个候选时，按已知协商详情的 create_user.user_id 核对，不根据第一条或在职状态擅自选择。

| 场景 | 逐人结果 | 合并结果与断言 |
|---|---|---|
| 三人查询，输入中重复指定第一人 | 1 / 1 / 2 | 仅查询三个唯一人员；去重 4 条，与完整个人基准 ID 集合相等 |
| 相同名称、不同协商 ID | 同一发起人 2 条、分两页 | 两条均保留，不按名称去重 |
| 三人且已完成 | 0 / 1 / 0 | 1 条，等于基准中原始状态 3/6 的集合 |
| 三人且协商中 | 1 / 0 / 2 | 3 条，等于基准中原始状态 2 的集合 |
| 三人且我发起的视图 | 0 / 0 / 0 | 共同条件不删除，完整空结果；缺少命中正例 |
| 三人且状态、类型、发起日期、部门共同筛选 | 1 / 0 / 0 | 1 条，对应已知匹配记录；每人保留同一筛选 |
| 顶部待我确认/定稿 | 逐页读取 | 3 条，与页面一致 |
| 顶部我已确认/定稿 | 成功空列表 | 0 条，与页面一致；缺少命中正例 |

“相同名称”一行为主场景内的集合断言，不是额外生产场景。多人合并结果没有生成统一服务端 token；各人的 has_more/token 独立处理。此轮生产未自然出现跨页重复协商或字段冲突，这两项由离线用例覆盖。

## Firefox 对照

直接操作生产 Firefox 页面，三名发起人分别单选：1、1、2 条。名称、编号、状态、确认人数与对应 MCP 集合一致；页面当前人员选择器单选，合并验证使用三次单选的结果并集。

4 条确认人数为 0/1、0/1、0/6、0/3；其中原始总体状态 6 的记录，页面与 Skill 均展示“协商完成”和“0/1 人已确认”。顶部待我确认为 3 条，我申请的和我已确认视图为空。最终恢复“我的协商 → 全部”，4 条，无临时筛选；未保存视图。

## 离线行为与安装回归

独立试用的主场景从 4 个原始列表项按长字符串 ID 去重为 3 条；重复人员不重复查询，同名不同 ID 保留，A 的 token 不带给 B，末页即使 token 非空也停止，按用户指定的 create_time 倒序排列。另核对 9 项追加请求：8 个已知状态及未知码回退、人数缺失/异常/0、共同条件缺失时不编造、两个未支持的确认筛选、字符串 403、分页 token 异常、字段冲突、缺少 ID、合并分页边界。

CLI/Skill 包回归测试、Skill 格式校验和 16 项安装脚本测试通过。重新构建仅更新内嵌 Skill，在隔离配置及临时目标中安装后逐文件比较：除安装器正常添加的 version: dev 元数据外，正文及附录与源码一致，包含新增的多人查询附录。首次逐字比较因版本行差异失败，按现有安装器规则修正校验后通过；测试新增的正式配置目录登记已清理，其他登记保留。未替换用户正式安装的 Skill，也未更新交付安装包；本次验证不声称旧任务已自动热加载新 Skill。

## 保留的限制

- “全部节点已确认”及抽屉“我是否可确认”的服务端筛选本次按要求不修改。
- 多人结果是逐人查询后的并集，没有服务端统一分页或快照一致性保证；跨页记录冲突须按 Skill 明示。
- 取消、拒绝、待发起、本人已确认等缺少生产命中样本的限制仍保留；空结果及离线用例不能替代这些正例。
- 不主动制造生产权限拒绝、缺 ID、异常人数或分页异常；离线行为和既有 CLI 模拟测试覆盖这些边界。
