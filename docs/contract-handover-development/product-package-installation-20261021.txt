合同交接 Skill 产品验证包
修订号：2026.10.21-group-flow.2
CLI 基线：正式版 contract-cli 1.9.8

本包内容
contract-handover/ 为完整 Skill 目录，含主文件、界面元数据及七份接口参考。
manifest.json 记录修订号、依赖和文件 SHA-256。
本包只更新交接 Skill，不包含 CLI、账号授权、配置、生产合同或人员数据。

本次变化
只给合同编号时，Skill 通过已有分组搜索接口自动取得真实父组 ID，并核对父组详情和完整成员列表。
已有可信父组 ID 时直接读取组接口，省略重复定位。
成员列表固定 needApproveRecord=false，不要求成员 contract/info 成功。
交接仍按父组整体提交，按真实父组类型和 ID 构造请求，不拆成成员写入。
成员完整性、接收人、权限、影响范围和既有确认要求继续保留。

父组 ID 自动定位
产品只需提供完整合同编号和接收人，不需要父组 ID 或页面链接。
Skill 优先复用已选合同；缺父组关系时，在同一环境与 user 授权下按编号查询原始分组。
父行 contractId 是父组候选，成员 assemblyId 和父组详情用于核对；搜索 group_id 不当父组 ID。
普通合同继续走普通合同流程；重名、多组、零命中或不完整结果按业务信息消歧，不默认第一条。
本包复用现有接口，没有修复成员 contract/info 的后端异常，也不要求该成员详情成功。

安装前
1. 核对本机 contract-cli version 为正式 1.9.8，并确认 api call --help 支持 --channel web。
2. 当前客户端的实际 Skill 目录中，应已有正式 1.9.8 配套的 auth、contract-cli-shared、contract-cli-contract-search 及其引用资源。
   按姓名或部门等条件搜索时，还需对应的配套人员、部门等 Skill。它们不在本包重复提供。
   正式版 shared 应明确允许已验证业务 Skill 使用 api call --channel web。
3. 配套依赖缺失时，先按正式 CLI 的安装说明确认实际目标目录和覆盖范围，安装配套 Skill，再覆盖本包交接 Skill。
4. 使用产品同事自己的生产 user 授权。通过官方授权页面登录，不传递 curl、Cookie、Token 或其他人的配置。

安装本修订
1. 确认客户端实际读取的用户 Skill 目录。Codex 通常为 ~/.codex/skills；其他客户端以其实际配置为准。
2. 将原 contract-handover 文件夹备份到 Skill 搜索目录之外。
3. 用本包 contract-handover 整个文件夹替换同名目录，避免多嵌套一层，也不要合并遗留参考文件。
4. 替换后不要立即运行 contract-cli skills install --force，它会装回 CLI 内嵌版本；后续全局升级 CLI 也可能同步覆盖本修订。
5. 完全退出客户端并新建会话，确认加载的 SKILL.md 中 metadata.revision 为 2026.10.21-group-flow.2。
   该修订号独立于 CLI 版本，CLI 继续保持 1.9.8。

产品验证流程
1. 只给完整合同编号和接收人，先要求只读预检，不提交交接。
2. 检查 Agent 自动补查父组，读取 contractAssembly/info 与 childrenInfo；成员分页到空页，核对父组前后 childrenCount 和原先选择的成员关系。
3. 核对接收人、当前与预期归属人/申请人，以及父组和全部成员的实际影响范围。
4. 用户确认同一份清单与接收人后，才提交一次父组交接请求。
5. 写后使用同一组接口回查父组与全部成员，并关联本次父组授权或新增历史；不要求每份成员另有独立授权记录。
6. 自动定位无精确命中、多组歧义、结果不完整、成员关系不一致、权限拒绝或结果不确定时，按 Skill 报告原因；不猜 ID、不切身份重试、不重复交接。

校验范围
本修订经过格式、引用与离线合成流程检查；生产只读验证了父编号定位、成员编号定位、零命中及完整三成员核对。
交付前未执行真实生产交接。
实际写入结果应由产品在获得明确授权后执行，并以写后回查为准。
