## 纠正初版判断

生产页面当前人员选择器为单选；选择第二个人会替换第一个。前端请求使用数组不等于 UI 已开启多选。CLI 按用户要求支持多选，服务端数组返回并集，验证方式是页面两次单选之和，而非声称页面已同时选中两个人。前端本次未修改。

顶部待我确认视图还会携带默认条件（例如协商中、待我确认/定稿）；点击筛选重置是恢复该视图默认条件，不能把它误当成清空所有筛选。在 Firefox 复测时检查了实际选中项，最终仅保留待我确认进行对照。

## 参数与响应边界

- 新字段：confirm_process_status_codes、confirmable_status_codes、create_employee_ids；Web 部门字段为 create_department_ids。
- 前两组字段严格限定取值，重复值与非法枚举拒绝；内部 ID 必须为正 int64 十进制字符串。
- Web 不接受 MCP 的 create_user_id、department_collection、page_token，避免 ID 或分页协议混用。
- Web 输入 page_index/page_size/order 映射 query，筛选字段映射页面 camelCase DTO。响应原样保持 content/totalElements/totalPages/pageIndex；最多 10000 条窗口。
- 固定 Timezone-Offset=-480，与本次中国标准时间页面对照一致。
- HTTP/业务 403、success=false 均返回失败，无自动身份/环境/通道切换。
