# Skill 安装 Ctrl+C 协作取消

## 2026-10-23

- 修复 `skills install` 收到 Ctrl+C 后仍覆盖文件、推进登记及打印成功的问题，保留默认文本和显式 JSON 输出约定。
- 沿既有安装调用链传递 context，新增兼容的 `InstallContext`；在元数据、资源暂存、备份/替换、校验及提交前检查取消；原 `Install` 与自动 `Sync` 保留后台 context 行为。
- 已开始替换时使用原事务回滚，恢复 Skill、管理标记及原登记；恢复不受取消 context 中止，失败保留 journal/backup。未增加锁，也未改变既有锁范围、顺序或非阻塞语义。
- 提交完成后不回滚；最终 JSON 输出前再次检查取消，通过 `committed` 和 `installation` 实绩说明已提交内容，避免误报未安装或已恢复。
- TDD 红例覆盖取消后继续安装和输出成功、继续读下一项元数据、完成日志/登记摘要阶段取消；回归覆盖入口、部分暂存、完整/单项/跳过、逐项替换、末项校验、恢复失败与后续恢复，并保留同时发生的文件错误。
- 真实 SIGINT 子进程测试在暂存中确认取消后释放读取，核验退出 130、JSON stdout 空、旧文件/第三方内容与登记不变；普通和 race 各重复 10 次通过。
- 全量 Go 测试、race、vet、CLI 冒烟及 macOS/Linux/Windows 构建通过；整体覆盖率 81.4%，CLI 包 82.8%，skillsync 包 84.4%；独立复审通过。验证仅使用临时目录和模拟资源，未操作真实业务或用户 Skill 目录。
- 协作取消不能强行打断单次文件系统调用；必要恢复完成后退出，新建空目标根目录可能保留。README、命令参考和帮助已同步，本地重新安装前保留旧二进制备份。
